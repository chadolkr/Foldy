# プロジェクト管理 (PMBOK 5 段階) の使い方

> 業種を問わず使えるプロジェクト文書の整理法です。米国のプロジェクトマネジメント協会 (PMI) の PMBOK ガイドが示す 5 つのプロセス群 (立ち上げ・計画・実行・監視コントロール・終結) の順にフォルダーを分けます。

## フォルダーごとに何を入れるか

| フォルダー | 入れるもの |
|---|---|
| **01_立ち上げ** | プロジェクト憲章、利害関係者一覧、立ち上げの承認 |
| **02_計画** | 範囲・スケジュール (WBS)・予算・品質・リスク・コミュニケーション計画 |
| **03_実行** | 作った成果物、議事録、作業資料 |
| **04_監視コントロール** | 週次・月次の進捗報告、変更要求、課題・リスクの記録 |
| **05_終結** | 最終報告、受け入れ確認書、教訓 (振り返り)、契約終了 |
| **99_保管** | 古いバージョン、もう使わないもの |

## 整理を続けるコツ

- 監視コントロールは実行と並行して回ります。報告や変更要求はその都度 04 に。
- 終わるときに教訓を 05_終結 に残すと、次のプロジェクトが楽になります。

## こんなときは別のスタイルを

- ソフトウェアを作るプロジェクト → **IT システム開発文書**
- 図面・モデルを複数のチームでやり取りする建設・設計 → **建設・設計の情報管理**
- 顧客ごとに契約・成果物だけを分ければ十分 → **顧客・プロジェクト業務**
