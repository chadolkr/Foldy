# IT システム開発文書 (ISO/IEC/IEEE 12207) の使い方

> ソフトウェア ライフサイクルの国際標準 ISO/IEC/IEEE 12207 の技術プロセスの順 (要件 → 分析 → 設計 → 実装 → 試験 → 移行 → 運用保守) で **文書** を分けます。ソース コードは Git リポジトリに置き、このフォルダーにはリポジトリの場所だけを書いておきます。

## フォルダーごとに何を入れるか

| フォルダー | 入れるもの | 標準のプロセス |
|---|---|---|
| **01_要件** | 依頼の受付、利害関係者の要件、要件定義書 | 利害関係者要件・システム/ソフトウェア要件の定義 |
| **02_分析** | 現状・業務分析、システム分析、妥当性検討 | ビジネスまたはミッションの分析、システム分析 |
| **03_設計** | アーキテクチャ、詳細設計、画面・データ設計 | アーキテクチャ定義、設計定義 |
| **04_実装** | 実装メモ、ビルド・デプロイ設定の説明、リポジトリの場所 | 実装、統合 |
| **05_試験** | 試験計画・シナリオ・結果、欠陥一覧 | 検証、妥当性確認 |
| **06_移行** | 切り替え・展開計画、データ移行、ユーザー教育 | 移行 |
| **07_運用保守** | 運用マニュアル、障害記録、変更・改善要求 | 運用、保守 |
| **99_保管** | 古いバージョン、もう使わないもの | — |

## 整理を続けるコツ

- 要件が変わったら 01 に新しいバージョンで (日付・v 番号)、古いものは 99_保管 へ。
- 試験結果にどの要件を確認したかを書いておくと、追跡しやすくなります。

## こんなときは別のスタイルを

- 業種共通のスケジュール・報告が中心 → **プロジェクト管理 (PMBOK 5 段階)**
- 顧客企業ごとの外注 → **顧客・プロジェクト業務**
