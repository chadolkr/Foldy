# IT 시스템 개발 문서 (ISO/IEC/IEEE 12207) 사용법

> 소프트웨어 수명 주기 국제 표준 ISO/IEC/IEEE 12207의 기술 프로세스 순서(요구사항 → 분석 → 설계 → 구현 → 시험 → 이행 → 운영·유지보수)로 **문서**를 나눕니다. 소스 코드는 Git 저장소에 두고, 이 폴더에는 저장소 위치만 적어 둡니다.

## 폴더별로 무엇을 넣나

| 폴더 | 넣는 것 | 표준의 프로세스 |
|---|---|---|
| **01_요구사항** | 요청 접수, 이해관계자 요구사항, 요구사항 정의서 | 이해관계자 요구사항·시스템/소프트웨어 요구사항 정의 |
| **02_분석** | 현황·업무 분석, 시스템 분석, 타당성 검토 | 업무 또는 임무 분석, 시스템 분석 |
| **03_설계** | 아키텍처, 상세 설계, 화면·데이터 설계 | 아키텍처 정의, 설계 정의 |
| **04_구현** | 구현 메모, 빌드·배포 설정 설명, 저장소 위치 | 구현, 통합 |
| **05_시험** | 시험 계획·시나리오·결과, 결함 목록 | 검증, 확인(밸리데이션) |
| **06_이행** | 전환·배포 계획, 데이터 이관, 사용자 교육 | 이행(전환) |
| **07_운영유지보수** | 운영 매뉴얼, 장애 기록, 변경·개선 요청 | 운영, 유지보수 |
| **99_보관** | 지난 버전, 더는 안 쓰는 것 | — |

## 유지 요령

- 요구사항이 바뀌면 01에 새 버전으로(날짜·v번호), 예전 것은 99_보관으로.
- 시험 결과는 어떤 요구사항을 확인했는지 적어 두면 추적이 쉬워요.

## 이럴 땐 다른 스타일을

- 업종 공통의 일정·보고 중심이라면 → **프로젝트 관리 (PMBOK 5단계)**
- 고객사별 외주라면 → **고객·프로젝트 업무**
