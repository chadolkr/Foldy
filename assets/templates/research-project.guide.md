# 연구·학습 프로젝트 사용법

> 읽고(문헌) → 모으고(데이터) → 분석하고 → 쓰고(원고) → 발표하는 흐름 그대로 칸을 나눕니다. 논문, 졸업 과제, 스터디 정리에 알맞습니다.

## 폴더별로 무엇을 넣나

| 폴더 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| **문헌** | 논문 PDF, 참고문헌 목록(.bib), 읽은 메모 | 내가 쓴 원고 |
| **데이터/원본** | 받거나 수집한 데이터 그대로 | 고친 데이터 |
| **데이터/정제** | 정리·가공한 데이터 | 원본 |
| **분석** | 분석 코드·노트북, 결과 표·그림 | 원본 데이터 |
| **원고** | 논문·보고서 원고와 버전 | 발표 자료 |
| **발표** | 슬라이드, 포스터 | 원고 |

## 예시 트리

```
센서연구/
├─ 문헌/
├─ 데이터/
│  ├─ 원본/
│  └─ 정제/
├─ 분석/
├─ 원고/
├─ 발표/
└─ README.md
```

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 논문 | 저자_연도_제목 | `Lee_2023_센서_융합.pdf` |
| 데이터 | 내용_날짜 | `설문_2026-11-18.csv` |
| 원고·분석 | 이름_v버전 | `원고_v0.3.docx` |

## 유지 요령

- 원본 데이터는 절대 고치지 않습니다. 가공은 정제 폴더에서 하고, 가공 방법은 분석 폴더의 코드로 남깁니다.
- 읽은 논문은 한 줄 요약을 README나 문헌 메모에 적어 두면 나중에 인용하기 쉽습니다.

## 이럴 땐 다른 스타일을

- 문서 한 건의 초안·검토·최종만 관리한다면 → **문서 작성 단계**
- 연구가 아니라 코드가 중심이라면 → **소프트웨어 프로젝트**
