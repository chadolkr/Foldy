# 研究・学習プロジェクトの使い方

> 読む (文献) → 集める (データ) → 分析する → 書く (原稿) → 発表する、という流れのとおりに区分を分けます。論文、卒業研究、勉強のまとめに向いています。

## フォルダーごとに何を入れるか

| フォルダー | 入れるもの | 入れないもの |
|---|---|---|
| **文献** | 論文の PDF、参考文献リスト (.bib)、読んだメモ | 自分が書いた原稿 |
| **データ/元データ** | 受け取ったり集めたりしたデータそのまま | 直したデータ |
| **データ/整形済み** | 整理・加工したデータ | 元データ |
| **分析** | 分析コード・ノートブック、結果の表・図 | 元データ |
| **原稿** | 論文・報告書の原稿とバージョン | 発表資料 |
| **発表** | スライド、ポスター | 原稿 |

## ツリーの例

```
センサー研究/
├─ 文献/
├─ データ/
│  ├─ 元データ/
│  └─ 整形済み/
├─ 分析/
├─ 原稿/
├─ 発表/
└─ README.md
```

## 名前の付け方

| 対象 | ルール | 例 |
|---|---|---|
| 論文 | 著者_年_タイトル | `Lee_2023_センサー_融合.pdf` |
| データ | 内容_日付 | `アンケート_2026-11-18.csv` |
| 原稿・分析 | 名前_vバージョン | `原稿_v0.3.docx` |

## 整理を続けるコツ

- 元データは決して直しません。加工は整形済みフォルダーで行い、加工の方法は分析フォルダーのコードに残します。
- 読んだ論文は 1 行の要約を README か文献メモに書いておくと、後で引用しやすくなります。

## こんなときは別のスタイルを

- 文書 1 つの下書き・レビュー・最終だけを管理する → **文書作成の段階**
- 研究ではなくシステム開発が中心 → **IT システム開発文書**
