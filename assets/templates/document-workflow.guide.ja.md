# 文書作成の段階の使い方

> 1 つの文書が通る段階でフォルダーを分けます。「いまどこまで進んだか」がフォルダーを見るだけで分かります。

## フォルダーごとに何を入れるか

| フォルダー | 入れるもの | 入れないもの |
|---|---|---|
| **01_下書き** | 書いている途中のファイルとそのバージョン | 人に送るファイル |
| **02_レビュー** | レビューを受けているファイル、もらったフィードバック | まだ書いている下書き |
| **03_最終** | 確定した最終版 1 つ | 複数のバージョン |
| **04_配布** | 実際に送ったファイル (PDF など)、送った日付 | 直すファイル |

## ツリーの例

```
事業計画書/
├─ 01_下書き/
│  ├─ 事業計画書_v0.1_下書き.docx
│  └─ 事業計画書_v0.2_下書き.docx
├─ 02_レビュー/
├─ 03_最終/
│  └─ 事業計画書_v1.0_最終_2026-11-18.docx
├─ 04_配布/
│  └─ 2026-11-18_事業計画書_投資会社.pdf
└─ README.md
```

## 名前の付け方

| 対象 | ルール | 例 |
|---|---|---|
| 作業ファイル | 文書名_vバージョン_状態 | `事業計画書_v0.2_下書き.docx` |
| 最終版 | 文書名_vバージョン_最終_日付 | `事業計画書_v1.0_最終_2026-11-18.docx` |
| 配布版 | 日付_文書名_送り先 | `2026-11-18_事業計画書_投資会社.pdf` |

## 整理を続けるコツ

- 段階を進めるときは **コピー** します。前の段階のファイルを消すと戻れなくなります。
- 「最終_本当に最終」の代わりにバージョン番号を上げてください。
- 03_最終 には常にファイルを 1 つだけ置きます。

## こんなときは別のスタイルを

- 顧客ごとに複数のプロジェクトを扱う → **顧客・プロジェクト業務**
- 論文・報告書を資料・データと一緒に書く → **研究・学習プロジェクト**
