# Go 프로젝트 사용법

> 실행 파일은 cmd, 비공개 코드는 internal, 공개 라이브러리는 pkg. internal 안의 코드는 컴파일러가 다른 모듈의 사용을 막아 줍니다.

## 폴더별로 무엇을 넣나

| 폴더 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| **cmd/앱이름** | main 패키지(진입점). 코드는 얇게 | 핵심 로직 |
| **internal** | 이 모듈 안에서만 쓰는 핵심 코드 | 외부에 공개할 API |
| **pkg** | 다른 프로젝트가 가져다 쓸 라이브러리 (선택) | 쓸 곳이 없는 코드 |
| **docs** | 사람이 읽는 문서 | — |

`pkg`는 필요할 때만 만드는 폴더라 미리보기에서 처음부터 체크가 풀려 있습니다. 작은 프로젝트라면 cmd와 internal만으로 충분합니다.

## 예시 트리

```
mytool/
├─ cmd/
│  └─ mytool/
│     └─ main.go
├─ internal/
├─ pkg/
├─ docs/
├─ go.mod
├─ README.md
└─ .gitignore
```

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 패키지 | 짧은 소문자 한 단어 | `scanner` |
| 파일 | snake_case.go | `file_walker.go` |
| 테스트 | 이름_test.go | `file_walker_test.go` |

## 유지 요령

- 처음에는 go.mod의 모듈 이름이 앱 이름뿐이므로, 저장소가 생기면 전체 경로로 바꿉니다.
- bin, dist 같은 빌드 결과는 커밋하지 않습니다.


## 이럴 땐 다른 스타일을

- 언어를 정하지 않은 일반 저장소라면 → **소프트웨어 프로젝트**
- 문서·설계가 중심이라면 → **문서 작성 단계**
