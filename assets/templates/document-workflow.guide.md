# 문서 작성 단계 사용법

> 문서 하나가 지나가는 단계를 폴더로 나눕니다. "지금 어디까지 왔나"가 폴더만 봐도 보입니다.

## 폴더별로 무엇을 넣나

| 폴더 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| **01_초안** | 작성 중인 파일과 버전들 | 남에게 보낼 파일 |
| **02_검토** | 검토를 받는 파일, 받은 피드백 | 아직 쓰는 중인 초안 |
| **03_최종** | 확정된 최종본 한 개 | 여러 버전 |
| **04_배포** | 실제로 보낸 파일(PDF 등), 보낸 날짜 | 고칠 파일 |

## 예시 트리

```
사업계획서/
├─ 01_초안/
│  ├─ 사업계획서_v0.1_초안.docx
│  └─ 사업계획서_v0.2_초안.docx
├─ 02_검토/
├─ 03_최종/
│  └─ 사업계획서_v1.0_최종_2026-11-18.docx
├─ 04_배포/
│  └─ 2026-11-18_사업계획서_투자사.pdf
└─ README.md
```

## 이름 규칙

| 대상 | 규칙 | 예 |
|---|---|---|
| 작업 파일 | 문서명_v버전_상태 | `사업계획서_v0.2_초안.docx` |
| 최종본 | 문서명_v버전_최종_날짜 | `사업계획서_v1.0_최종_2026-11-18.docx` |
| 배포본 | 날짜_문서명_받는곳 | `2026-11-18_사업계획서_투자사.pdf` |

## 유지 요령

- 단계를 넘길 때는 **복사**합니다. 앞 단계의 파일을 지우면 되돌아갈 수 없습니다.
- "최종_진짜최종" 대신 버전 번호를 올리세요.
- 03_최종에는 항상 한 파일만 둡니다.

## 이럴 땐 다른 스타일을

- 고객별로 여러 프로젝트를 다룬다면 → **고객·프로젝트 업무**
- 논문·보고서를 자료·데이터와 함께 쓴다면 → **연구·학습 프로젝트**
