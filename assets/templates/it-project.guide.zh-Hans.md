# IT 系统开发文档（ISO/IEC/IEEE 12207）使用方法

> 按软件生命周期国际标准 ISO/IEC/IEEE 12207 的技术过程顺序（需求 → 分析 → 设计 → 实现 → 测试 → 移交 → 运维）划分 **文档**。源代码放在 Git 仓库中，此文件夹只记录仓库位置。

## 每个文件夹放什么

| 文件夹 | 放什么 | 对应的标准过程 |
|---|---|---|
| **01_需求** | 需求受理、干系人需求、需求规格说明书 | 干系人需求、系统/软件需求定义 |
| **02_分析** | 现状与业务分析、系统分析、可行性研究 | 业务或任务分析、系统分析 |
| **03_设计** | 架构、详细设计、界面与数据设计 | 架构定义、设计定义 |
| **04_实现** | 实现备忘、构建与部署配置说明、仓库位置 | 实现、集成 |
| **05_测试** | 测试计划、场景与结果、缺陷清单 | 验证、确认 |
| **06_移交** | 切换与部署计划、数据迁移、用户培训 | 移交 |
| **07_运维** | 运维手册、故障记录、变更与改进请求 | 运行、维护 |
| **99_归档** | 旧版本、不再使用的 | — |

## 保持整洁的诀窍

- 需求变更时，在 01 中以新版本保存（日期和 v 编号），旧版本移到 99_归档。
- 在测试结果中写明验证了哪些需求，便于追溯。

## 这些情况适合其他风格

- 以各行业通用的进度和报告为主 → **项目管理（PMBOK 5 阶段）**
- 按客户公司划分的外包 → **客户与项目工作**
