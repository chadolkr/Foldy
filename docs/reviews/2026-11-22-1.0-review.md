## 1. 다국어 번역

방법: 언어 파일(1,731개 글 × 5개 언어)을 스크립트로 전부 검사하고, 코드·XAML·설명서·사이트에 남은 한국어를 찾고, 무작위 표본과 주요 화면 글을 직접 읽었다.

- **빠진 글·자리 표시({0})**: 네 언어 모두 빠진 글 0, `{0}` 번호가 한국어와 다른 글 0, 잘못된 중괄호(앱이 멈출 수 있는 형식 오류) 0.
- **남은 한국어 (화면)**: T1~T4. T1은 Windows 셸 이름표를 쓰는 길(`ShellInfo.TypeName`)이 폴더·확장자 없는 파일에 한국어 고정값을 돌려줘서 생겼다. 확장자가 있는 파일은 원래처럼 Windows가 주는 이름(Windows 언어)을 쓴다. 언어별 자동 시험이 이것을 못 잡은 이유: 시험이 보는 목록 화면의 폴더 행에서 종류 열을 읽지 않는다. 1.0 뒤 언어별 UI 시험에 "종류 열" 확인을 더하면 좋다.
- **일부러 남긴 한국어 (그대로 둠)**: 빠른 검색의 한국어 말 알아듣기(설명서에 "한국어만"이라고 적혀 있음), MCP가 AI에게 주는 답, 로그·진단 기록, 서비스 기록에서 찾는 표시 말, 저장되는 태그 값, 이전 버전 보관 폴더 이름(`.foldy\이전 버전`, 숨김 폴더·설명서에 적힘), 예전 한국어 폴더를 계속 쓰는 규칙.
- **용어 일관성**: 휴지통(Recycle Bin / Papelera / ごみ箱 / 回收站), 정리(Tidy / Ordenar / 整理), 되돌리기, 금고(vault / caja fuerte / 金庫 / 保险箱), 색인 서비스, 잠긴 메모는 언어마다 하나로 맞다. 중국어 잠긴 메모만 두 가지였다(T5).
- **자연스러움**: 표본을 읽은 결과 네 언어 모두 기계 번역 티가 거의 없고 Foldy의 "친절한 말투"(Shall I…? / ¿Los ordeno…? / 〜しましょうか? / 要…吗？)가 살아 있다. 잘림 위험이 큰 사이드바 이름은 0.9.38에서 이미 줄였다.
- **설명서(F1)**: 영어·스페인어·일본어·중국어판에 남은 한국어는 예시("다운로드 정리해줘")와 예전 한국어 폴더 이름 안내뿐(의도). 
- **사이트**: 네 언어 페이지에 한국어 없음. 영어 README만 오래된 "번역 중" 문구(T6).
- **업데이트 진행 창(PowerShell)**: 번역 글을 작은따옴표 문자열로 넣을 때 `'`를 `''`로 바꾸고, PowerShell이 따옴표로 보는 ‘ ’ 문자는 어느 언어에도 없다. 파일은 BOM 있는 UTF-8로 써서 일본어·중국어도 깨지지 않는다.
- **폴더 이름 번역**: 템플릿·정리가 만드는 폴더 이름에 Windows가 금지하는 글자(`<>:"/\|?*`, 끝 점·공백)가 들어간 번역은 없다.

## 2. 코드 리뷰 (크래시·데이터 손실 중심)

이번에 본 곳과 결과:

- **정리 실행·되돌리기**(`OrganizeExecutor`): 덮어쓰지 않음(`overwrite: false`), 계획 뒤 같은 이름이 생기면 다시 피함, 폴더는 다른 드라이브로 옮기지 않음, 모든 이동은 저널에, 되돌릴 때 그사이 바뀐 파일은 그 자리에 두고 알림, 만든 빈 폴더만 지움. 문제 없음. L3만 뒤로.
- **빨리 지우기**(`FastDelete`): 드라이브 맨 위·Windows·사용자 폴더 자체 거부, 링크는 링크만. 지난 리뷰 그대로.
- **SFTP 이동**: 복사가 모두 성공한 뒤에만 원본을 지움, 건너뛴 파일이나 링크가 든 원본은 지우지 않음.
- **문서 그림 모드**(`--doc-screenshots`): 폴더를 통째로 지우는 길이 있지만 `FOLDY_DATA_DIR`가 있어야 하고 대상 이름이 `FoldyDemo`/`FDemo`일 때만. 사용자 폴더를 지울 수 없다.
- **UI 예외**: 처리되지 않은 UI 예외는 기록·보고 후 앱을 살려 둔다(`e.Handled = true`).
- **언어 고르기**(`Loc.Resolve`): 설정 → Windows 언어 → 영어 순, 번체 중국어는 영어. 없는 글은 영어, 그다음 키 이름(멈추지 않음).
- **버전 1.0.0**: 앱 비교(`System.Version`)·서비스 비교(semver)·MSI ProductVersion 모두 0.9.44 < 1.0.0으로 올바르게 판단한다. 1.0.0 태그로 자동 업데이트가 정상 동작한다.
- CI: main은 0.9.41~0.9.44 모두 통과.

## 3. 보안

- **0.9.38~0.9.44 변경분**: 새 네트워크 연결·새 권한·새 파일 쓰기 경로 없음. 위험해 보일 수 있는 곳(업데이트 진행 창 스크립트에 번역 글 넣기, 번역 폴더 이름으로 경로 만들기, 문서 그림 모드의 폴더 정리)을 봤고 문제 없다.
- **V3 (서명 키)**: 아직 사용자 설정 전으로 보인다(이 세션은 저장소 설정을 볼 수 없음). 이 PR은 release.yml 작업에 `environment: release`를 넣었다. 키를 옮기기 **전에도** 저장소 시크릿을 그대로 읽으므로 릴리스는 지금처럼 돈다. 사용자가 키를 Environment로 옮기면 그때부터 태그 릴리스 작업만 키를 읽는다.
- **PR #19**: 내용은 좋지만 그 뒤 main이 바뀌어 `release.yml`, `pages.yml`, `README.md`, `README.en.md`, `docs/DECISIONS.md`에서 충돌한다. 1.0을 막지 않는다(없어도 업데이트 서명·해시 검사는 그대로). 1.0 뒤 충돌을 풀어 병합하고, 병합 뒤 사용자 설정(비공개 취약점 신고, Dependabot, CodeQL 기본 설정 끄기)을 한다.
- 지난 리뷰의 V8~V10, L2·L6·L7은 받아들인 그대로다.
