## 1. 막는 문제와 고친 방법

### B1. 덮어쓰기 복구가 파일을 잃게 할 수 있음
- **원인**: `VersionHistory.Preserve`는 대상 파일을 보관 폴더로 **옮긴다**(같은 드라이브라 즉시 끝남). 복사 엔진은 "덮어쓰기"를 고른 충돌마다 먼저 이것을 부르고 엔진에 덮어쓰기를 맡긴다. 그 파일의 복사가 끝내 안 되면(취소, 원본이 다른 프로그램에 잠김, 디스크 부족, 검증 실패) 대상 자리는 빈 채로 끝났다. 파일은 숨김 보관 폴더에 있지만, 그 자리에 파일이 없으니 "이전 버전" 메뉴로 찾을 수도 없다. 또 보관할 때마다 한도 정리를 해서, 여러 파일을 "모두 덮어쓰기"하면 앞서 보관한(아직 덮어쓰지 않은) 파일이 지워질 수 있었다.
- **고침**:
  - 복사 작업이 끝나면(완료·실패·취소 모두) 덮어쓰려고 옮겨 둔 파일 중 **자리가 빈 것은 제자리로 돌려놓는다** (`VersionHistory.PutBack`, `NativeCopyFileOperationService.PutBackUnwritten`).
  - 복사 작업 중에는 한도 정리를 미루고 작업 끝에 한 번 한다 (`Preserve(prune: false)` → `PrunePending`).
  - 한도 정리는 **원래 자리에 파일이 없는 보관본은 지우지 않는다**(그 내용의 유일한 사본일 수 있음). 이런 보관본도 7일이 지나면 지운다.
  - 폴더 비교 "맞추기"는 복사가 안 된 파일을 바로 제자리로 돌려놓고, 중간에 취소해도 그때까지 한 것은 되돌리기 기록에 남긴다. USB·네트워크 드라이브에서 쓰는 `.foldy-bak`은 원래 파일이 그대로일 때만 지운다.
- **시험**: `VersionHistoryTests`(돌려놓기, 여러 파일 보관 중 한도), `FolderCompareTests`(원본이 열려 있을 때), `CopyEngineM3Tests`(원본이 잠겨 복사 실패 → 제자리, 성공하면 그대로).

### B2. 2GB가 넘는 파일을 금고·잠긴 파일에서 꺼낼 수 없음
- **원인**: 넣기(`SecureZip.Write`)와 확인(`Verify`)은 조금씩 읽어 큰 파일도 됐지만, 꺼내기·풀기·미리보기·잠근 뒤 확인은 `ReadEntry`로 항목 전체를 `MemoryStream`에 담았다. .NET 메모리 스트림은 2GB를 넘을 수 없어 `IOException: Stream was too long`이 났다. 잠긴 파일 열기는 이 오류를 "암호 틀림"으로 보여 줬고, 금고 꺼내기는 오류를 받지 않아 작업이 멈췄다.
- **고침**: 항목을 **파일로 바로 푼다** (`SecureZip.ExtractEntry`, `SecureZip.Extract`). 미리보기는 앞부분 32MB까지만 읽는다(`ReadEntryHead`). 잠근 뒤 확인은 해시를 바로 계산한다(`HashEntry`). 꺼내다 한 항목이 실패하면 쓰다 만 파일만 지우고 다음 것을 계속하며, 못 꺼낸 것은 이름과 이유를 보여 준다(금고에는 그대로 있음). 틀린 암호와 읽기 오류를 구분한다.
- **확인**: 4.4GB 파일로 잠그기(41초) → 확인 → 앞부분 읽기 → 풀기(72초), 내용이 같았다. 4GB가 넘는 항목도 ZIP64로 정상 저장된다. 고치기 전 길(`ReadEntry`)은 같은 파일에서 `Stream was too long`으로 실패하는 것도 확인했다.
- **시험**: `VaultTests.Picked_entries_are_streamed_to_files_and_preview_reads_only_the_head`.

### B3. 공간을 쓰는 작업은 시작 전에 빈 공간부터 (사용자 요청)
- **경위**: 사용자 요청 셋(2026-11-22). "금고에 넣는 용량 제한을 미리 알려 줘, 시간 낭비하다 초과하면 알려 주는 건 시간 낭비", "제한이 있으면 미리 알려 사용자 시간을 낭비하지 않게, 이 원칙을 저장", "복사하거나 금고에 넣거나 등등 여유 공간이 있는지 미리 확인하고 가능할 때만 작업을 시작", 그리고 "공간이 부족하면 폴더 분석 → 정리하도록 도와주면 어떨까?".
- **실제 한도**: 금고·잠긴 파일에 **크기 제한은 없다**(4GB 넘는 파일은 ZIP64, 꺼낼 때는 파일로 바로 풀기, B2). 끝까지 못 가게 하는 것은 둘뿐이다. (1) 대상 드라이브의 빈 공간: 금고는 폴더 옆에 생기고 원본은 확인이 끝날 때까지 그대로 두므로 넣는 크기만큼 더 든다. (2) FAT32 드라이브(오래된 USB 등)는 파일 하나가 4GB-1바이트까지다. 파일 개수는 ZIP64라 65,535개를 넘어도 된다(아래 "확인").
- **고침**: 공통 부품 `Foldy.Core.Space.DiskSpace`(빈 공간·형식 보기, 작은 파일은 4KB 단위로 올려 셈, 모르면 막지 않음)와 복사 엔진의 `space.rs`.

  | 작업 | 전 | 지금 |
  |---|---|---|
  | 복사·이동 (복사 엔진) | 확인 없음: 쓰다가 가득 차면 파일마다 실패 | 파일 목록을 본 직후, **한 바이트도 쓰기 전에**(대상 폴더도 만들기 전에) 확인. 덮어쓰기·충돌은 크기 차이만 센다. 모자라면 오류 `-9`/`-10`으로 멈추고 작업 창에 "빈 공간 부족: N 필요, M 남음"과 [공간 늘리기]·[다시 시도] |
  | 복사·이동 (엔진을 못 쓸 때 Windows 복사) | Windows가 시작 전에 확인 | 그대로 |
  | 금고 넣기·파일 잠그기 | 확인 없음: 암호화가 끝날 무렵 실패 | **암호를 묻기 전에** 확인. 100MB가 넘으면 "크기 제한은 없어요, 빈 공간이 약 N 필요해요(지금 M 남음)" 한 줄 |
  | 금고 꺼내기·잠긴 파일 풀기 | 확인 없음 | 꺼내기 전에 확인 |
  | 폴더 비교 맞추기 | 확인 없음 | 맞추자고 묻기 전에 드라이브마다 확인 |
  | 로그 압축 | 확인 없음 | 시작 전에 확인 (새 zip 크기 + 다시 쓰는 월별 zip) |
  | 이전 버전 옆에 꺼내기 | 확인 없음 | 확인 |

  | 이전 버전 되돌리기, 정리 도구(폴더·바탕화면·다운로드), 지우기·휴지통·중복 정리, 템플릿 폴더 만들기 | — | 같은 드라이브 안에서 옮기거나 공간을 늘리는 일이라 확인할 것 없음 |
  | 이미 있던 것 | 로그 정리 알림(줄일 양이 빈 공간의 5%를 넘을 때), 폴더 분석 드라이브 고르기에 남은 공간 표시 | 그대로 |

- **모자랄 때**: 안내 창(금고 등)에는 [공간 늘리기]·[다시 확인]·[취소]가, 작업 창(복사·이동)에는 [공간 늘리기]·[다시 시도]가 나온다. [공간 늘리기]는 새 화면 없이 사이드바의 "공간 늘리기"(폴더 분석)를 **그 드라이브로** 연다. 정리한 뒤 [다시 확인]·[다시 시도]를 누르면 하던 일을 처음부터 다시 확인하고 이어 한다. FAT32 문제는 공간을 늘려도 풀리지 않으므로 다른 드라이브를 쓰라고만 한다. SFTP 서버는 폴더 분석을 열 수 없어 [다시 시도]만.
- **덤**: 파일이 아주 많은 금고는 꺼내기·확인이 파일 수의 제곱만큼 느렸다(zip 항목을 찾을 때마다 처음부터 훑음). 항목 표를 한 번만 만들게 고쳤다.
- **원칙**: [DESIGN-PRINCIPLES.md](../DESIGN-PRINCIPLES.md) 1.8 "제한은 미리 알려 시간을 아낀다", PR 점검표 한 줄.
- **시험**: Rust `space::tests` 3개, `job::tests::not_enough_space_stops_before_writing_anything`(대상 폴더도 만들지 않는지), `DiskSpaceTests` 6개, `SpaceTests` 3개(문구, 작업 창 단추, 공간 늘리기 → 다시 시도).
- **확인**: 7만 개 파일 금고 넣기·확인·꺼내기 시험은 이 점검 환경에서 돌리는 중 (결과를 덧붙인다).

## 2. 다국어 (en·es·ja·zh-CN)

**일부러 남긴 한국어**는 PR #22 기록과 같다(빠른 검색의 한국어 말 알아듣기, AI가 받는 답, 로그·진단, 저장되는 값, 예전 한국어 폴더 규칙).

## 3. 다시 본 곳 (문제 없음)

- **복사·이동 엔진**: 이동은 대상 기록과 검증(크기·시각)이 끝난 파일만 원본을 지운다. 실패·건너뛴 파일이 든 원본 폴더는 남는다. 저널로 이어 하기, 취소하면 쓰다 만 대상 정리.
- **지우기**: 빨리 지우기는 드라이브 맨 위·Windows·사용자 폴더 자체를 거부하고, 링크는 링크만 지운다. 휴지통 보내기 기본.
- **정리 도구**: 정리 위저드·바탕화면·다운로드·관리 방식·템플릿 적용은 덮어쓰지 않고(이름이 겹치면 건너뛰거나 번호), 모두 되돌리기 기록을 남긴다. 템플릿 되돌리기는 바뀌지 않은 파일과 빈 폴더만 지운다.
- **업데이트**: update.json Ed25519 서명 확인 → 파일 SHA-256 확인 → 설치하는 동안 파일을 잠가 바꿔치기 막기 → 실패하면 되돌리기. 0.9.44 → 1.0.0 버전 비교 정상.
- **설치(MSI)**: 새 파일을 먼저 쓰고 이전 제품을 정리(작업 표시줄 고정 유지), 낮은 버전 설치는 자동 되돌리기 때만, 서비스 설치·중지·제거, 지연 시작.
- **AI 연결(MCP)**: 도구 6개 모두 읽기만, 네트워크 경로 거절, 결과 개수 상한.
- **네트워크·느린 드라이브**: 드라이브마다 한 줄로 기다리기, 색인 없는 드라이브는 천천히 모으기, 이전 버전은 이 PC의 고정 디스크에만.
- **금고 만들기**: 조금씩 읽어 쓰고, 끝까지 풀어 확인한 뒤, 빠진 파일이 없을 때만 원본 정리를 제안.

## 5. 시험

- 새 시험 5개: `VersionHistoryTests` 2, `FolderCompareTests` 1, `VaultTests` 1, `CopyEngineM3Tests` 1(Windows, 실제 복사 엔진).
- B3 시험: Rust 4개(Windows CI), `DiskSpaceTests` 6개, `SpaceTests` 3개 — Linux에서 C# 9개 통과, Rust는 Windows 대상으로 빌드·clippy 통과(실행은 Windows CI).
