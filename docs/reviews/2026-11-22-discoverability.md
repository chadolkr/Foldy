# 기능 찾기 점검: 처음 쓰는 사람이 찾기 어려운 기능 (2026-11-22)

> 사용자 의견: "좋은 기능이 있어도 처음 사용하는 사람은 기능이 어디 있는지 모르는 것들이 있다."

사이드바(맨 위 넷, 네 묶음 메뉴, 아래 세 아이콘), 패널 도구 줄, 기능키 줄, 파일·폴더·드라이브 오른쪽 클릭, 단축키, 명령 목록(Ctrl+Shift+P),
무엇이든 찾기(빠른 검색)의 낱말, 한 줄 제안, 빈 화면을 모두 훑었다. 기준은 디자인 원칙의 "할아버지 할머니도 편하게: 설명서를 읽지 않고, 처음 보는 순간 쓸 수 있어야 한다".

## 찾기 어려웠던 기능

| # | 기능 | 있던 곳 | 왜 못 찾나 | 이번에 한 것 |
| --- | --- | --- | --- | --- |
| 1 | **덮어쓴 파일 되살리기 (이전 버전)** | 파일 오른쪽 클릭에만 | 조사에서 필요도 5위("잃어버린 것 되살리기")인데 메뉴 어디에도 없었다 | 지키기 메뉴에 "덮어쓴 파일 되살리기 (이전 버전, 고른 파일)", 명령 목록·무엇이든 찾기("실수로 덮어썼어", "복구")에서도 |
| 2 | **AI 연결** | 더 보기 메뉴 안, 한 번 뜨는 제안 | "연결하기" 묶음에 없고, 이름이 "AI 연결 (MCP)"라 낯설다 | 연결하기 메뉴 맨 위에 "AI에 연결 (Claude 등)…", 묶음 설명에도. 무엇이든 찾기 "클로드", "ChatGPT" |
| 3 | **네 묶음(찾기·정리하기·지키기·연결하기) 안의 기능 전부** | 사이드바 묶음 단추 | 누르면 메뉴가 열린다는 표시가 없어 그냥 이름표처럼 보인다 | 묶음 단추 오른쪽에 › 표시 (사이드바를 접으면 숨음) |
| 4 | **무엇이든 찾기로 기능 부르기** (다른 언어) | 빠른 검색 | 말하듯 부르는 낱말이 한국어만 있어, 영어·스페인어·일본어·중국어 화면에서는 기능 이름에 딱 맞아야만 찾혔다 | 기능 낱말 38개를 5개 언어로(`qi.<명령 id>`), 새로 숨은 기능 낱말 추가 |
| 5 | **이미지만 보기** | 찾기 메뉴, Ctrl+Shift+I | 도구 줄 단추는 첫 화면 단순화(2026-11-19)로 뺐다. 사진 폴더에서 이런 보기가 있는 줄 모른다 | 사진이 30장 넘고 7할 이상인 폴더를 처음 열 때 한 줄 제안 [이미지만 보기] (한 번만) |
| 6 | **두 창 비교·맞추기** | 찾기 메뉴 | "찾기" 묶음에 있어 짐작하기 어렵다. 백업 확인처럼 쓰임새가 큰데 쓸 순간을 모른다 | 양쪽 창에 이름이 같은 폴더가 열리면 한 줄 제안 [두 창 비교] (한 번만), 무엇이든 찾기 "백업 확인", "차이" |
| 7 | **지워도 되는 폴더 찾기** | 정리하기 메뉴 아래쪽 | 개발 폴더에서 공간을 아끼는 기능인데 메뉴 끝에 있다 | node_modules·__history·bin+obj가 있는 폴더를 열면 한 줄 제안 (한 번만) |
| 8 | **템플릿으로 폴더 만들기** | 사이드바 맨 위, Ctrl+Shift+N | 이미 보이지만, 가장 쓸 법한 순간(새 빈 폴더)에는 아무 안내가 없었다 | 빈 폴더 화면에 "다른 창에서 끌어다 놓으면 복사, 새 폴더는 F7" 한 줄과 [템플릿으로 폴더 만들기] |
| 9 | **새 폴더 단추의 단축키** | 기능키 줄 F7 | 마우스를 올리면 "새 폴더 (Ctrl+Shift+N)"이라고 나왔는데, Ctrl+Shift+N은 템플릿이다(잘못된 안내) | "지금 폴더 안에 새 폴더 만들기 (F7)"로 고침 |
| 10 | **자주 쓰는 폴더에 고정** | 머리글 오른쪽 핀 단추 | "핀 버튼으로 지금 폴더를 고정하세요"가 어디를 누르라는지 모호 | "위 오른쪽의 핀 단추를 누르면 지금 보는 폴더가 여기에 생겨요" |
| 11 | 폴더 설명 편집, 미리보기, 새 탭, Git, 설정, 정리 도우미, 개발 캐시 등 | 더 보기·단축키·명령 목록 | 무엇이든 찾기에 부를 낱말이 없었다 | 낱말 추가 ("이 폴더가 뭔지", "열지 않고 보기", "커밋" …) |

## 그대로 둔 것 (이유)

- **Git Blame, 관리자 명령 프롬프트, 버그 진단 모드, 로그 폴더, 설정 파일 열기**: 개발자·문제 해결용이라 처음 쓰는 사람이 찾을 일이 적다. 명령 목록·무엇이든 찾기에는 있다.
- **사이드바 폴더·드라이브의 오른쪽 클릭(새 탭에서 열기, 반대 패널, 순서 바꾸기, 폴더 분석)**: Windows에서 늘 쓰는 방식이고, 폴더 분석은 맨 위 [공간 늘리기]로도 닿는다.
- **작업 완료 말고 다른 표시(태그)**: 명령 목록에만 있다. 쓰는 사람이 적고, 늘리면 정리하기 메뉴가 길어진다.
- **새 메모·잠긴 메모·금고의 자리**: 다른 스레드가 메모 잠금·금고를 고치는 중이라 건드리지 않았다.
- **도구 줄의 이미지만 보기 단추**: 2026-11-19 사용자 결정(첫 화면 단순화)대로 다시 넣지 않고, 한 줄 제안으로 대신했다.

## 한 줄 제안의 규칙 (새로 더한 셋)

- 지금 폴더를 열 때 이미 불러온 목록만 본다(디스크를 더 읽지 않음). 내 PC의 드라이브 폴더에서만, 느린 드라이브는 빼고.
- 한 번에 하나, 같은 제안은 **평생 한 번**: 띄우는 순간 기억한다(데이터 폴더의 hints-dismissed.txt, `once|<규칙>`). 그냥 두면 45초 뒤 저절로 사라진다. 누를 단추는 [그 기능]과 [닫기]뿐, 확인 창은 없다.
- 설정의 정리 알림을 끄면 이것도 뜨지 않는다.
- 순서: 원래 있던 정리 제안(다운로드·바탕화면·로그) → 두 창 비교 → 지워도 되는 폴더 → 이미지만 보기.

## 시험

- 단위 시험: `DiscoveryHintsTests`(규칙), `QuickIntentTests`(한국어 숨은 기능 낱말, 네 언어 낱말, 모든 언어에 같은 낱말 키).
- 화면 시험(FlaUI): 연결하기·지키기 메뉴에 새 항목, 빈 폴더의 안내와 [템플릿으로 폴더 만들기] → 템플릿 창, 사진 폴더의 한 줄 제안 → 이미지만 보기 켜짐.
- 화면 캡처 장면 `discover`, `discover-menu-connect`, `discover-menu-protect` (CI ui-shots).
