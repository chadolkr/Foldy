# 안내는 손이 있는 자리에 — 상태 칸에만 뜨는 안내 점검 (2026-11-25)

사용자 말: "메세지가 커서 action 위치와 달라 볼 수 없다", "우리 디자인 원칙은 액션하는 위치에 메세지가 있어야 한다."

끌어 놓기 안내(1.10.1)를 아래 상태 칸에서 마우스 커서 바로 아래로 옮기면서, 같은 원칙에 어긋나는 다른 안내를 찾았다.
`Shell.Status`(주 창 아래 상태 칸)에 쓰는 곳 약 70곳을 보고, **누른 곳과 상태 칸이 멀리 떨어진 것**만 골랐다.
아직 고치지 않았다(목록만). 고칠 때는 `Foldy.UI.Controls.CursorHint`(커서 아래 말풍선) 또는 누른 단추 바로 아래 말풍선을 쓴다.

## 고친 것 (이번 PR)

| 안내 | 누르는 곳 | 바꾼 곳 |
| --- | --- | --- |
| 이미 이 폴더에 있어요 (두 창이 같은 폴더) | 파일을 끄는 마우스 | 커서 바로 아래 |
| 폴더를 자기 안에 넣을 수 없어요 (새로 더함) | 파일을 끄는 마우스 | 커서 바로 아래 |

## 고칠 것 (먼저 할수록 위)

| --- | --- | --- | --- |

## 그대로 둬도 되는 것

- **상태 칸 바로 위 단추**: 먼저 파일을 골라 주세요·반대쪽 창에 열린 폴더가 없어요 (`ops.selectFirst`, `ops.noOtherFolder`)는 F5·F6 단추 바로 아래라 눈에 들어온다. 다만 키보드(F5)로 눌렀을 때는 목록에 눈이 있으므로, 1번을 고칠 때 함께 본다.
- **잘 된 일 알림·진행 알림**: 복사해 둠, 고정했어요, 휴지통으로 옮겼어요, 업데이트 확인 중, 목록 읽는 중 등. 알아서 사라지고 놓쳐도 문제가 없다.
- **키 결과**: 숨김 파일 보이기(Ctrl+H), 화면 크기. 화면이 바로 바뀌어 결과가 보인다.
