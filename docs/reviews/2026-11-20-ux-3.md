# UX 점검 3차 (2026-11-20, 0.9.1 기준 전체 화면)

기준: [DESIGN-PRINCIPLES.md](../DESIGN-PRINCIPLES.md) 1.2 — 할아버지 할머니도 설명 없이, 켜고 끄기는 같은 자리, 큰 누르는 곳, 뜻이 보이는 아이콘, Windows 표준 방식. 방법: 모든 장면 자동 캡처(33장) + UI 자동 테스트로 보이는 버튼 크기 전수 검사.

## 고친 것

| # | 화면 | 문제 | 고친 내용 |
| --- | --- | --- | --- |
| 1 | 폴더 트리 | 숨기기(트리 안 «)와 보이기(도구 줄 오른쪽 끝)가 다른 곳 | 도구 줄 맨 왼쪽(트리 바로 위) 버튼 하나로 켜고 끔. 켜져 있으면 눌린 모양, 툴팁은 누르면 일어날 일 |
| 2 | 사이드바 | ≡ 버튼으로만 접기, 너비 조절 불가 | 오른쪽 가장자리를 끌어 넓히고 줄이기(아주 좁히면 아이콘만, 다시 끌면 펼침). ≡ 버튼은 그대로 같은 자리 |
| 3 | 이미지만 보기 | 켠 뒤 끄는 곳이 안 보임 | 찾기 메뉴 항목에 체크 표시와 "이미지만 보기 끄기"로 상태를 보여 줌 |
| 4 | 폴더 트리 펼치기 화살표 | 16×16이라 맞추기 어려움 | 28×28 화살표, 줄 높이 28 |
| 5 | 경로(브레드크럼) 칸 | 높이 19px | 28px 이상 |
| 6 | 기능키 줄(F2~Del) | 높이 23px | 32px |
| 7 | 최근 폴더 줄 | 높이 26px | 32px |
| 8 | 사이드바 제목 옆 버튼(고정·지우기) | 26×24 | 32×32 |
| 9 | 탭 닫기 × | 22×22, 마우스를 올려야 보임 | 28×28, 늘 흐리게 보임 |
| 10 | 경계선 끌기(트리·두 창·미리보기·사이드바) | 잡는 곳 4~6px | 9~10px (보이는 선은 그대로 가늘게) |
| 11 | 대화 창 | 글씨·단추 작음 | 글씨 17, 단추 높이 38. 처음 설정은 글씨 18 |
| 12 | 처음 실행 | 글자 크기를 모르고 시작 | 처음 설정: 글자 크기를 실제 파일 목록 모양(보통~가장 크게)으로 보고 고르고, 밝기를 고른 뒤 둘러보기. 업데이트 때는 묻지 않고 상태 줄로 알림 |

자동 검사: `HitTargetTests` — 메인 창에서 보이는 모든 버튼이 28×28 이상 (스크롤 막대 부품 제외). 통과.

## 괜찮았던 것

- 사이드바 네 묶음 아이콘(찾기 돋보기, 정리 화살표, 지키기 자물쇠, 연결 고리, 휴지통)은 표준 아이콘이고 이름이 함께 보임. 접으면 툴팁.
- 설정·도움말·더 보기 아이콘(톱니·물음표·…)은 Windows 표준.
- 터미널 버튼 3개는 실제 프로그램 아이콘(명령 프롬프트·PowerShell·관리자 방패).

## 제안 (사용자 결정 필요, 바꾸지 않음)

- 도구 줄 아이콘만 있는 버튼(새로 고침, 터미널 3개)에 짧은 글자를 함께 쓸지: 넓은 화면에서만 글자를 보이는 방법이 있음. 좁은 창에서는 공간이 모자람.
- 폴더 목록의 크기·날짜 열 머리글을 눌러 정렬하는 것이 처음 사용자에게 보이는지: 지금은 화살표(^)만. 첫 사용 때 한 번 알려 주는 한 줄 제안을 붙일 수 있음.
