# 버전 규칙

Foldy는 세계 표준인 **유의적 버전(Semantic Versioning 2.0.0, https://semver.org/lang/ko/)** 을 따릅니다 (사용자 결정 2026-11-22).

버전은 `주.부.수(MAJOR.MINOR.PATCH)` 세 자리입니다.

| 자리 | 올리는 때 | 예 |
|---|---|---|
| **주(MAJOR)** | 예전 것과 **호환이 깨지는** 변경. 이전 Foldy가 만든 파일·설정을 새 Foldy가 그대로 못 읽거나, 쓰던 방식이 사라질 때 | 금고 형식을 바꿔 예전 금고를 변환해야 함, 설정 파일 구조가 바뀜 |
| **부(MINOR)** | **호환되는 기능 추가**. 새 기능, 눈에 띄는 기능 확장 | 새 정리 도구, 새 언어, 새 템플릿 묶음 |
| **수(PATCH)** | **호환되는 버그 수정**. 고장 고침, 번역·문구·문서 고침, 성능 개선 | 줌인 위치 고침, 잘린 글자 고침 |

- 부를 올리면 수는 0으로, 주를 올리면 부와 수를 0으로 되돌립니다 (0.9.44 → 0.10.0 → 0.10.1 → 1.0.0).
- 한 릴리스에 여러 종류가 섞이면 **가장 큰 자리**를 올립니다 (기능 하나 + 버그 고침 셋 = 부).
- 각 자리는 **숫자로** 비교합니다: 0.10.0은 0.9.44보다 새 버전입니다.

## Foldy에서 "호환"이 뜻하는 것

semver의 "공개 API"는 Foldy에서 사용자가 의지하는 것들입니다. 이것을 깨면 주(MAJOR)를 올립니다.

- 사용자 파일 형식: 잠긴 메모·잠긴 파일·금고(`.foldylock`, `.foldyvault`), 메모 묶음(`.textpack`), 폴더 메모(`.foldy.md`: 관리 방식·태그)
- 설정과 데이터: `settings.json`, `keymap.json`, 세션, 내 템플릿(`*.foldy-template.json`의 schemaVersion)
- 다른 프로그램과의 약속: MCP 도구(이름·입력·결과), 명령줄 옵션(`--mcp` 등), 업데이트 채널(update.json과 서명)

화면 배치·문구·기본값이 바뀌는 것은 호환을 깨는 것으로 보지 않습니다 (부 또는 수).

## 1.0 전 (0.y.z)

semver는 0.y.z를 "처음 개발 중"으로 봅니다. Foldy는 0.x에서도 같은 규칙(부 = 기능, 수 = 버그 수정)을 지키고, 호환을 깨는 변경은 0.x에서도 피하거나 변환 기능과 함께 냅니다. 1.0.0은 [1.0 점검표](release-1.0-checklist.md)를 마치면 냅니다.

## 미리보기(베타) 버전

베타 채널에는 `0.10.0-beta.1`, `0.10.0-beta.2`처럼 **붙임표 + 미리보기 표시**를 씁니다. semver 순서대로 `0.10.0-beta.2 < 0.10.0`이라, 정식이 나오면 베타 사용자도 정식으로 올라갑니다. `+빌드정보`는 쓰지 않습니다(비교에 쓰이지 않음).

## 어디에 적나

- `Directory.Build.props`의 `<Version>` 한 곳. 태그는 `v` + 버전(`v0.10.0`).
- 업데이트 비교: 앱(`AppUpdater.IsNewer`, System.Version 숫자 비교)과 서비스(`engine/foldy-update/src/version.rs`, semver 순서)가 같은 규칙으로 비교합니다.
- 설치본 제약: MSI의 ProductVersion은 주·부 255 이하, 수 65535 이하, MSIX는 네 자리 숫자(`주.부.수.0`)입니다. 이 범위 안에서 씁니다.
- 바뀐 점은 [CHANGELOG.md](../CHANGELOG.md)에 버전마다 적습니다.
