# 색인 영속화 (FoldyIndexer 빠른 시작)

서비스를 시작할 때마다 $MFT를 전부 읽어 색인을 다시 만들면 약 12초(180만 항목)가 걸린다. 볼륨별 스냅샷을 저장해 두었다가 시작할 때 불러오고, 그 뒤에 생긴 변경만 USN 저널로 따라잡는다. 스냅샷이 조금이라도 의심스러우면 쓰지 않고 지금까지처럼 전체를 다시 만든다. 새 파이프 메시지는 없다 (프로토콜 변경 없음).

## 파일

- 위치: `%ProgramData%\Foldy\Index\<볼륨 GUID>.idx` (`--index-dir`로 바꿀 수 있고, 지정하면 ACL을 건드리지 않는다).
- 폴더 ACL: SYSTEM·Administrators만 (모든 사용자의 파일 이름이 들어 있고, 변조된 스냅샷을 일반 사용자가 넣지 못하게 한다). 분석 DB 폴더와 달리 로그온 사용자 읽기도 주지 않는다.
- 내용: 매직 `FLDYIDX1`, 형식 버전, 볼륨 일련번호(부트 섹터), USN 저널 ID, 다음 USN, 루트 경로, 노드·하드링크 표, 이름 풀(쓰레기 제외), 맨 끝에 앞 전체의 64비트 해시. 검색용 접힌 이름은 저장하지 않고 읽을 때 다시 만든다 (파일이 작아진다). 코드: `foldy-ntfs/src/index/snap.rs`.
- 크기: 항목당 약 55~90바이트 (시험 측정은 아래).

## 저장

- 전체 구축을 마친 직후 한 번, 그 뒤에는 바뀐 것이 있을 때 10분마다, 서비스가 정상 종료될 때(`Indexer::save_all`, 서비스 정지 중 상태로 표시).
- 읽기 잠금 아래에서 메모리에 직렬화하고(검색은 계속된다, USN 반영만 잠깐 기다린다), 잠금 밖에서 `.idx.tmp`에 쓰고 `sync_all` 한 뒤 이름을 바꿔 넣는다. 중간에 죽어도 옛 파일이 남는다.
- 저장하는 위치(next USN)는 색인을 읽기 전에 잡는다. 색인이 위치보다 조금 앞서 있어도, 복원 뒤 같은 변경을 다시 적용하면 같은 결과가 된다 (변경은 "레코드를 다시 읽어 덮어쓰기"이므로 멱등, 시험 있음).
- 저널을 따라가기 시작하기 전(구축 중, 복원 중 종료)에는 저장하지 않는다.

## 시작

1. 스냅샷 파일을 읽고 해시·형식을 검사한다. 
2. 검사 항목이 모두 맞아야 쓴다: 볼륨 일련번호 같음, 저널 ID 같음, 저장 위치가 저널의 `first_usn` 이상이고 `next_usn` 이하, 스냅샷의 루트 경로가 이 볼륨.
3. 색인을 공개(검색 가능)하고, 저장 위치부터 저널 끝까지 읽어 반영한다. 이때부터 검색이 되며, 상태 메시지는 "스냅샷 불러옴 … 따라잡는 중" → "스냅샷 복원 완료 …".
4. 위 어느 단계든 실패하면(파일 없음·깨짐·불일치·저널 읽기 오류) 색인을 비우고 전체 구축으로 간다. 이유는 상태 메시지와 stderr에 남는다. 전체 구축은 읽는 동안 `INDEXING` 상태(검색은 NOT_READY, 클라이언트가 폴백)라서 지금과 같다.

복원은 서비스 시작 때 한 번만 시도한다. 실행 중 저널이 끊겨 다시 구축할 때는 항상 전체 구축이다.

## 측정

`foldy-index --bench C:` (관리자 PowerShell)는 구축 시간 옆에 스냅샷 저장·읽기·복원 시간과 저널 따라잡기 시간을 출력한다. 관리자 권한 없이는 `foldy-index --bench-scan <폴더>`로 폴더 열거 색인에 대해 같은 스냅샷 시간을 잴 수 있다. 서비스 로그(`stderr`)에도 시작 방식별 시간이 한 줄 남는다: "MFT 색인 완료: N개, 시간" 또는 "스냅샷 복원 완료: N개, 시간".

측정 (2026-11-19, 릴리스 빌드, 이 개발 PC):

| 대상 | 항목 수 | 전체 구축 | 스냅샷 읽기+복원 | 파일 크기 | 저장 (직렬화+쓰기) |
| --- | --- | --- | --- | --- | --- |
| `C:\Windows` 폴더 열거 | 151,263 | 10.3초 (열거) | 0.15초 | 12.8MB | 14ms + 25ms |
| `C:\Users` 폴더 열거 | 736,347 | 85.5초 (열거) | 0.99초 | 38.0MB | 106ms + 108ms |

- 복원 시간 대부분은 접힌 이름 풀을 다시 만드는 것(`C:\Users`에서 0.93초). 항목 180만이면 대략 2~3초로 예상한다.
- **MFT 직접 구축(약 12초/180만)과 저널 따라잡기의 실측은 못 했다**: 이 환경은 관리자 권한이 없어 볼륨 핸들을 열 수 없다 (`--bench C:`는 종료 코드 2). 위 표의 "전체 구축"은 MFT가 아닌 폴더 열거라 비교 대상이 아니고, 복원 쪽 숫자만 의미가 있다. 관리자 PowerShell에서 `foldy-index --bench C:`를 한 번 돌려 이 표에 MFT 행을 추가해야 한다.

## 시험

- `foldy-ntfs` `index::snap`: 왕복(경로·크기·하드링크·검색), 이름 쓰레기 제거, 모든 바이트 변조·모든 길이 절단이 오류, 다른 형식 버전 거부.
- `foldy-index` `persist::tests` (가짜 저널 `JournalSource`): 저장 위치부터 따라잡기, 스냅샷 없이 같은 저널을 적용한 결과와 동일, 중복 적용 멱등, 일련번호·저널 ID·오래된 위치·끝보다 뒤·다른 볼륨·깨진 파일·읽기 오류 때 전체 구축으로 폴백(색인이 비워짐), 취소, 임시 파일 후 이름 바꾸기, 저널을 따라가기 전에는 저장 안 함.
- 관리자 권한이 필요한 시험은 없다 (실제 볼륨 경로는 `--bench`로만 확인).

## 하지 않은 것

Subscribe(폴더 변경 알림 파이프 메시지)와 FileSystemWatcher 대체는 범위에서 뺐다 (단순함·안정성 우선). 설계서의 변경 알림은 아직 남아 있다.
