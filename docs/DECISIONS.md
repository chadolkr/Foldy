## 2026-11-22 · 짧은 소개는 본 장면을 다시 띄우지 않고 새 장면만 (사용자 의견, 1.2.1)
- **경위**: 1.2.0으로 업데이트하니 이미 본 짧은 소개가 첫 화면에 다시 떴다. "한번 본것은 안보게 해야한다", "기능 쇼츠를 나누어서 이미 본것은 안보게 새로운 것은 쇼츠를 보게 하면 어떨까?" 원인은 2026-11-21에 정한 "다시 설치하거나 업데이트한 뒤 처음 켤 때도 보이기"(버전이 바뀌면 다시 띄움).
- **결정 (2026-11-21 결정을 바꿈)**: 장면마다 이름(tour.qs, tour.space …)을 두고, 본 장면을 데이터 폴더 `tour-seen.txt`에 한 줄씩 기억한다. 업데이트·다시 설치 뒤에는 아직 안 본 장면만 한 번 보여 주고, 없으면 아무것도 띄우지 않는다. 건너뛰어도 본 것으로 친다. 처음 설치와 ? → 짧은 소개 보기는 전부 보여 준다.
- **예전 기록**: 장면별 기록 전(1.2.0까지) 소개를 본 사람(`tour-shown.txt`만 있음)은 그때 있던 13장면을 모두 본 것으로 친다(`ShortsSeen.Before121`, 바꾸지 않는 목록). 새 기능 장면은 장면 목록에만 더하면 업데이트한 사람에게 그것만 뜬다.
- **다른 안**: 버전마다 한 번만(다시 전부 뜸, 사용자가 귀찮아한 그대로), 업데이트 뒤 아예 안 띄우기(새 기능을 모름).

## 2026-11-22 · Foldy가 띄운 창을 닫으면 Foldy 창을 앞으로 (1.2.1, 사용자 제보)
- **경위**: "잠김메모를 저장하고 닫으면 Foldy 창이 내려가서 안보인다." Windows는 주인(Owner)이 있는 창이 닫힐 때 주인이 아닌 z 순서의 다음 창(다른 프로그램)을 앞으로 올리기도 한다. 잠긴 메모는 안내 창(암호)이 먼저 닫히고 메모 창이 열리는 흐름이라 특히 잘 생겼다.
- **결정**: 메모 창 하나만 고치지 않고, 앱 전체에서 주인이 있는 모든 창이 닫히기 직전(아직 보일 때) 주인 창을 먼저 앞으로 올린다(`OwnerFocus`, Window.Loaded 클래스 처리기로 모든 창에). 금고·안내·설정·AI 연결 창도 같은 문제를 가질 수 있어서다.
- **하지 않는 경우**: 닫히는 창이 활성 창이 아닐 때(5분 뒤 저절로 잠기는 메모, 다른 앱을 연 뒤 닫히는 창), 주인 창을 최소화해 뒀을 때, 닫기가 취소됐을 때. 다른 프로그램을 쓰는 사람 앞으로 Foldy를 끌어오지 않게.
- 자동 테스트(FlaUI): 새 잠긴 메모를 만들고 [잠그고 닫기] → Foldy 주 창이 맨 앞인지.

## 2026-11-22 · 처음 쓰는 사람도 기능을 찾게 (사용자 의견, 1.2.0)
- **경위**: "좋은 기능이 있어도 처음 사용하는 사람은 기능이 어디 있는지 모르는 것들이 있다." 앱 전체를 훑어 찾기 어려운 기능 11가지를 정리했다(docs/reviews/2026-11-22-discoverability.md).
- **결정 (새 화면·새 큰 기능 없이, 기능을 빼지 않고)**:
  1. **사람이 찾아볼 묶음에 넣기**: 오른쪽 클릭에만 있던 "덮어쓴 파일 되살리기(이전 버전)"를 지키기 메뉴에, 더 보기에만 있던 "AI에 연결"을 연결하기 메뉴 맨 위에. 원래 자리도 그대로.
  2. **묶음 단추가 메뉴라는 표시**: 찾기·정리하기·지키기·연결하기 오른쪽에 ›.
  3. **알맞은 순간에 한 번만 한 줄 제안**: 사진이 많은 폴더 → [이미지만 보기], 양쪽 창에 이름이 같은 폴더 → [두 창 비교], node_modules·bin/obj 등이 있는 폴더 → [지워도 되는 폴더 찾기]. 평생 한 번(띄우는 순간 기억), 그냥 두면 45초 뒤 사라짐, 확인 창 없음, 정리 알림 설정을 따름.
  4. **빈 폴더 화면**: "다른 창에서 끌어다 놓으면 복사돼요. 새 폴더는 F7이에요." 한 줄과 [템플릿으로 폴더 만들기].
  5. **무엇이든 찾기 낱말을 5개 언어로**: 한국어에만 있던 기능별 쉬운 말을 번역 원본(`qi.<명령 id>`)으로 옮기고 숨은 기능 낱말을 더했다.
  6. 잘못된 안내 고침: 새 폴더 단추 툴팁이 Ctrl+Shift+N(템플릿)이라 했던 것 → F7. 자주 쓰는 폴더가 비었을 때 문구를 어디를 누르는지 알게.
- **왜**: 디자인 원칙 "배워야 쓸 수 있으면 실패", "필요할 때 그 자리에서 한 줄 제안". 투어를 늘리거나 첫 화면 단추를 늘리는 대신, 이미 있는 자리(묶음 메뉴·한 줄 제안·빈 화면·무엇이든 찾기)를 쓴다.
- **다른 안**: 도구 줄에 이미지만 보기 단추 다시 넣기(2026-11-19 첫 화면 단순화 결정과 어긋나 하지 않음), 처음 실행 때 기능 투어 늘리기(배워야 쓰는 방식이라 하지 않음), 기능마다 "새 기능" 배지(지저분해지고 사라지게 하기 어려움).
- **건드리지 않은 것**: 새 메모·잠긴 메모·금고 자리(다른 스레드에서 고치는 중), 개발자 기능(Blame·관리자 터미널 등)은 명령 목록·무엇이든 찾기로 충분.
- **SemVer**: 기능이 보이는 자리와 제안을 더한 것이라 둘째 자리(1.2.0, 1.1.0은 이 PR 없이 먼저 나감).
## 2026-11-22 · 잠긴 메모·파일 잠그기·금고를 처음 써도 알 수 있게 (1.0.2, 사용자 전달)
- **경위**: 사용자가 주변 사람 반응을 전했다: "메모 잠금, 금고 기능이 직관적이지 않아. 어떻게 해야할지 모르겠다네". 새 기능 동결 중이라 기능은 그대로 두고 화면 흐름·문구·안내만 고쳤다.
- **막히던 곳과 고친 것**
  1. **무엇인지 모름**: [지키기] 메뉴가 "새 잠긴 메모 (지금 폴더에)", "암호 걸기 (고른 파일)", "금고에 넣기 (고른 폴더)"뿐이라 셋의 차이를 알 수 없었다 → 항목마다 무엇에 쓰는지 한마디: "잠긴 메모 쓰기 · 비밀번호 같은 글 적어 두기", "파일 잠그기 · 암호를 넣어야 열려요", "폴더를 금고에 넣기 · 폴더째 잠가요".
  2. **눌러도 아무 일이 없는 것처럼 보임**: 파일·폴더를 먼저 고르지 않고 누르면 아래 상태 줄에 작은 글씨만 나왔다 → Windows 고르기 창("잠글 파일을 골라 주세요", "금고에 넣을 폴더를 골라 주세요")을 바로 띄운다. 지금 폴더가 내 PC 폴더가 아니면(처음 화면·서버) 잠긴 메모가 조용히 안 만들어지던 것은 '문서' 폴더에 만든다.
  3. **말이 섞임**: 같은 일을 "암호 걸기"·"잠그기"·"잠긴 파일"로 섞어 불렀다 → 파일은 "잠그기/잠긴 파일", 폴더는 "금고"로 통일(오른쪽 단추 메뉴 "🔒 잠그기 (암호)…").
  4. **암호 정하기**: 묻는 말이 경고("잊으면 열 수 없어요")뿐이라 무엇을 하라는지 몰랐다 → "열 때 쓸 암호를 정해 주세요"로 시작. 8글자 제한은 틀린 뒤에야 나왔다 → 칸 이름에 "암호 (8글자 이상)", 둘째 칸은 "같은 암호를 한 번 더"(사용자 원칙: 제한은 미리 알리기).
  5. **만든 뒤 어디 있는지 모름**: 잠긴 메모·잠긴 파일·금고를 만들면 파일 목록에서 그 파일을 골라 보여 주고, 메모 창 위쪽에 "'문서' 폴더에 '새 메모.memo.foldylock'로 저장했어요. 다시 열 때는 이 파일을 두 번 누르세요"를 적는다. 끝 안내도 "두 번 누르고 암호를 넣으면 열려요".
  6. **원래 파일 처리**: "암호가 없는 원본은 어떻게 할까요?"만 물었다 → 원래 파일이 아직 암호 없이 남아 있다는 것을 말하고, "원래 것은 휴지통으로 (추천)"을 앞에.
  7. **잠긴 파일 열기**: 미리보기 뒤 "어떻게 할까요? [풀어서 열기]" → 풀면 옆에 암호 없는 파일이 생기고 잠긴 파일은 남는다고 먼저 말한다. 연 뒤 묻는 말도 "계속 잠가 둘 거면 풀어 둔 파일을 지우고, 잠금이 필요 없으면 잠긴 파일을 휴지통으로", 단추는 "잠긴 파일 그대로 두기" / "잠금 그만 쓰기 (잠긴 파일은 휴지통으로)".
  8. **금고 열기**: 꺼낸 파일이 어디로 가는지 꺼낸 뒤에야 알았다 → 목록 위에 "꺼낸 파일은 옆의 'OO' 폴더에 암호 없이 나와요 (금고 안에도 그대로 남아요)". 단추는 "체크한 것 미리 보기/꺼내기".
- **그대로 둔 것**: 암호·암호화 방식, 5분 뒤 자동 잠금, 확인 단계(바로 지우기만 한 번 더 묻는다).
- **금고에 파일 더 넣기 (사용자 결정: "이번 PR에 같이 넣기")**: 동결 중이지만 사용자가 골랐다. 금고를 연 화면에 **[파일 더 넣기]**: 파일 고르기(여러 개) → 같은 이름이 있으면 [둘 다 두기 (새 것은 (2))] / [금고 안의 것을 바꾸기] / [취소] → 시작 전에 공간 확인(금고 크기 + 넣는 크기) → 옆에 새 금고(`.foldyvault.adding`)를 다 쓰고 모든 항목을 풀어 확인한 뒤에만 바꿔 끼움(실패하면 새 것을 지우고 원래 금고는 그대로) → 넣은 원래 파일 처리(휴지통 추천). 넣는 파일은 금고 맨 위에. 금고·잠긴 파일은 넣지 않는다. 같은 암호를 그대로 쓴다(열 때 넣은 암호). 다른 안: 금고 zip에 항목만 덧붙이기 → 목록(index)도 암호화돼 있어 어차피 다시 써야 하고, 덧붙이다 끊기면 금고가 망가질 수 있어 택하지 않음.
- 5개 언어 모두. 자동 테스트: [지키기] 메뉴 설명과 폴더 고르기 창, 새 잠긴 메모의 암호 칸 안내(FlaUI). 화면 점검에 장면 다섯 개(secure-*) 추가.

## 2026-11-22 · 업데이트·다시 설치는 AI 연결용 Foldy(--mcp)를 끝내고 진행 (1.0.2, 사용자 결정)
- **경위**: 1.0.1 업데이트가 "열려 있는 다른 Foldy 창이 닫히기를 기다리고 있어요"에서 멈췄다. 노트북에서 보니 Foldy 창은 없고 Antigravity·Claude가 띄운 `Foldy.exe --mcp` 두 개만 있었고, 서비스는 "Foldy가 끝나지 않아 설치를 미룸"을 남겼다. 사용자: "업데이트나 재설치할 경우 강제종료시키고 설치하는 걸로 하자".
- **결정**: 업데이트 서비스는 창 Foldy가 모두 닫혔을 때 AI 연결용 Foldy를 끝내고 설치한다(명령줄의 `--mcp`로 구별, 끝내기 직전에 다시 확인). 시작 감시·실행 중 확인도 AI 연결용은 세지 않는다. 설치 프로그램(MSI)도 InstallValidate 전에 AI 연결용 Foldy를 끝낸다(다시 설치·제거·업데이트 모두). AI 연결용은 읽기 전용이고 상태가 없어, AI 앱이 다음에 다시 띄우면 된다.
- **창 Foldy는 그대로 기다린다**: 앱이 업데이트할 때 스스로 닫히고(작업 중이면 "작업이 끝나면 업데이트"), 복사·이동을 끊지 않기 위해서다.
- **적용 시점**: 기다리는 쪽은 이미 깔린 서비스라, 1.0.2가 깔린 뒤의 업데이트부터 효과가 있다. 1.0.1로 가는 지금은 AI 앱을 끄면 된다.
- 업데이트 창 제목의 "1.0.1(으)로"는 "1.0.1 버전으로"로 바꿨다(숫자 뒤 조사).

## 2026-11-22 · 미리보기: DRM·암호로 보호된 파일은 오류가 아니라 안내로 (1.0.1, 사용자 요청)
- **경위**: "미리보기 기능에서 파일이 DRM 걸려있는 경우 에러로 표시하지 말고 DRM 걸려서 못보여주는 걸로 알려줄 수 있니?" → "반영하자". Office·PDF는 Windows 미리보기 처리기가 실패해 "미리 볼 수 없음 (처리기 오류)"로만 나왔다.
- **결정**: 미리보기 전에 파일 앞 64KB를 본다(`FileProtectionCheck`). 확장자가 말하는 형식(Office는 ZIP·복합 문서, PDF는 %PDF, 그림은 그 머리)과 다르고, 알려진 다른 형식도 아니며, 머리 뒤 내용이 암호문처럼 고르면(바이트 엔트로피 7.3 이상) DRM. Office 권한 관리로 암호화된 문서(복합 문서 안 DRMEncrypted…·DRMContent 이름)도 DRM, 강한 암호화 이름이면 암호. 확실하지 않으면 평소처럼 미리보기를 해 본다.
- **특정 보안 제품의 표시는 찾지 않는다**(회사 정보 규칙, docs/no-company-info.md): 제품마다 다른 머리 대신 "형식이 다르고 암호문 같다"로 본다. 화면 문구도 "DRM"·"문서 보안"만 쓴다.

## 2026-11-21 · 개발자 정리 세 가지 (0.9.29, 사용자 승인 · 기능 동결 예외)

- **3) 개발 캐시 정리**: npm·NuGet·pip·Yarn·pnpm·Docker 빌드 캐시. 깔린 도구만, **공식 명령만**(폴더를 직접 지우지 않음), 다시 받을 수 있는 것만. Docker는 `builder prune`만(이미지·컨테이너·볼륨 안 건드림). 되살릴 수 없으니 크기를 보여 주고 한 번 확인.
- **넣지 않기로 한 것**: 레지스트리 청소, 텔레메트리·서비스·Windows 업데이트 끄기 같은 최적화 트윅, UWP 앱 삭제, 브라우저 프로필 정리, 잠긴 파일 핸들 강제로 끊기, 환경 변수·hosts 자체 편집기, 심볼릭 링크 만들기. 파일 관리와 상관없거나 되돌리기 어렵고, 회사 PC 보안 정책과 부딪힌다.

- **교훈**: 권한에 따라 갈리는 검사는 관리자·보통 권한 둘 다에서 확인한다. 개발 PC 수동 점검 M13으로 남긴다.

## 2026-11-20 · 빠른 검색 (Ctrl+Space, 사용자 요청·기능 동결 예외)
- **결정**: macOS Spotlight처럼 어디서든 Ctrl+Space로 화면 가운데 큰 검색 칸을 연다. 한 칸에서 찾는 것: Foldy 기능(명령), 파일·폴더(색인 DB, 색인이 없으면 지금 폴더 안), 앱(시작 메뉴 바로 가기), Windows 설정 항목(ms-settings:), 자주 쓰는/최근 폴더(위쪽에), 간단 계산·단위 변환(입력하면 바로 결과, Enter로 복사). 결과는 종류별 묶음, 맨 위에 "가장 알맞은 것" 하나, 오른쪽에 미리보기. Enter 열기·실행, Ctrl+Enter 들어 있는 폴더 보기, Esc·바깥 누르면 닫기. 기능은 띄어 쓴 낱말·초성(ㅅㅈ → 설정)으로도 찾는다.

"다운로드 정리해줘", "메모 쓸래"처럼 말하듯 쳐도 끝말을 다듬고(해줘·할래·쓸래 → 쓰기…) 기능마다 붙인 쉬운 말(QuickIntent.Keywords)로 맞춘다. 문장으로 물으면 "이걸 할까요? Enter를 누르면 시작해요"로 대답하고, Enter면 그 기능의 **기존 대화 창**이 이어서 한 단계씩 묻는다. 외부 AI나 전송은 쓰지 않는다.
- **하지 않은 것 (복잡해서)**: 검색 창 안에서 여러 단계 대화를 새로 만드는 것. 정리 도구들이 이미 대화 창으로 한 단계씩 묻기 때문에 그것을 그대로 쓰는 쪽이 단순하다. Ctrl+Space를 "Foldy에게 말 걸기" 하나의 입구로 삼아 첫 화면 버튼을 줄이는 것은 써 본 뒤 사용자 동의를 받고 정한다.
- **넣지 않은 것**: 웹 검색·사전(밖으로 아무것도 보내지 않는다). 태그·메모 내용·SFTP·Git 검색은 써 보고 정한다.
- **단축키 겹침**: 전역 단축키(RegisterHotKey)로 등록한다. 다른 프로그램이 이미 쓰거나, 중국어·일본어 입력기가 설치돼 있으면(Ctrl+Space가 입력 전환 키) 겹친다고 본다. 겹치면 조용히 넘어가지 않고 알리고, 비어 있는 키 후보(Ctrl+Shift+Space, Ctrl+Alt+Space, Ctrl+Alt+F, Win+Shift+F 중 실제로 비어 있는 것)와 [직접 눌러서 정하기], [Foldy 안에서만 쓰기]를 보여 준다. 확인은 처음 설정(글자 크기·밝기 다음)에서 하고, 업데이트 때는 묻지 않고 등록만 하다가 실패할 때만 알린다. 설정 → 단축키에서 언제든 바꾼다. 시험용 실행(FOLDY_DATA_DIR)에서는 등록하지 않는다.
- **찾기 장면: 냄새 잘 맡는 블러드하운드 (사용자 결정)**: 파일을 찾으면 축 늘어진 귀와 이마 주름의 블러드하운드가 코를 바닥에 대고 킁킁 → 귀를 펄럭이며 쌩 달려가 → 폴더를 물고 꼬리를 흔드는 0.5초 장면과 "킁킁! 0.03초 만에 1,284개 물어 왔어요"를 보인다. 못 찾으면 고개를 갸웃한다. Foldy 고유의 단순한 도형 그림(특정 캐릭터 아님), 대사는 한 곳(나중에 리소스)에. 애니메이션은 Windows 애니메이션 설정이 아니라 Foldy 설정의 "애니메이션 사용"을 따른다(농구 애니메이션과 같음).

## 2026-11-20 · 빨리 지우기 (사용자 요청·기능 동결 예외)
- **결정**: 지우려는 곳에 파일이 **5,000개 이상**이면 지우기 전에 대화 창으로 묻는다. [휴지통으로 (되살릴 수 있어요)]가 기본, [빨리 지우기]를 고르면 "휴지통에도 남지 않아 되살릴 수 없어요, 중간에 멈춰도 이미 지운 것은 돌아오지 않아요"를 한 번 더 알리고, 그 확인의 기본 단추는 [그만두기]다(Enter 실수 방지). Shift+Delete(영구 삭제)로 지울 때도 같은 창이 나온다.
- **왜 5,000개**: Windows 휴지통은 파일 수천 개부터 눈에 띄게 느려지고(목록을 휴지통 데이터베이스에 하나씩 기록), 그보다 적으면 묻는 창이 오히려 방해가 된다. 세는 데는 2초까지만 쓰고, 다 못 세면 "○개 넘게"로 보인다.
- **방법**: 외부 명령(robocopy·rd) 없이 Foldy가 직접 병렬로 지운다. 폴더마다 안의 파일을 여러 스레드로 지우고(로컬 드라이브는 CPU 수×2, 최대 16), 비면 가장 깊은 폴더부터 지운다. 네트워크 드라이브는 동시에 4개만(회사 보안 드라이브 같은 느린 곳도 무리하지 않게). 읽기 전용·숨김·시스템 속성은 풀고 지운다. 긴 경로(260자 넘음)도 지운다. 정션·심볼릭 링크는 **링크만 지우고 안으로 들어가지 않는다**(다른 곳의 원본 보호). 작업 창에 지운 개수가 보이고 언제든 [취소]할 수 있다.
- **지우지 않는 곳**: 드라이브 맨 위, Windows, Program Files, ProgramData, 사용자 폴더 자체, 바탕화면·문서 폴더 자체는 빨리 지우기를 거절한다(휴지통으로만).
- **구현 위치**: 처음에는 Rust 엔진 안에서 하려 했으나, 하는 일이 "파일 하나씩 DeleteFileW"라 C#(.NET 파일 API = 같은 Win32 호출)으로 Foldy.Core에 두었다. 같은 병렬 방식이고 테스트(링크 보호·긴 경로·취소·보호 경로)를 쉽게 붙일 수 있다. 엔진 경계(FFI)를 늘리지 않는다.
- **애니메이션**: 영구 삭제와 같은 "경기장 밖" 장면.
