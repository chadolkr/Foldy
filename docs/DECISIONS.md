# 결정 기록

정한 것을 짧게 남긴다: 날짜, 무엇을, 왜, 다른 안. 최근 것이 위.

## 2026-11-20 · 0.9.0 → 0.9.1
- **경위**: 0.9.0 태그의 릴리스 빌드가 CI에서 실패했다. 관리자 권한 러너에서 UI 자동 테스트가 띄운 Foldy가 "관리자 해제(Deelevate)"로 다시 떠서 테스트가 프로세스를 놓쳤고, 화면 자동 점검의 작업 창 캡처가 작은 화면에서 그림 밖을 잘랐다. 둘을 고치고(시험용 데이터 폴더 FOLDY_DATA_DIR이면 다시 띄우지 않음, 자르기를 그림 안으로) 같은 내용을 0.9.1로 냈다. 0.9.0은 배포되지 않았다.
- **왜 0.9.1인가**: 이미 올라간 태그를 옮기면(강제) 기록이 꼬인다. 번호를 하나 올리는 쪽이 단순하고 안전하다.

## 2026-11-19 · 테스트 자동화 방침
- **결정**: 테스트는 최대한 자동으로. UI 자동 테스트는 FlaUI(UI Automation)로 짜서 GitHub Actions의 Windows 러너에서 돌린다(Playwright는 WPF에 못 씀). 모든 화면을 실제로 띄워 찍는 자동 점검(doc-screenshots -Strict)도 CI에서 돈다. 일반 릴리스는 자동 테스트만 통과하면 배포하고, 끝까지 자동화가 안 되는 수동 점검(UAC 클릭, 회사 프록시, 느린 보안 드라이브 등, docs/TESTING.md)은 큰 릴리스(0.9·1.0) 전이나 관련 코드가 바뀌었을 때만 돌린다.
- **왜**: 수동 점검 때문에 자동 배포가 막히면 안 된다.

## 2026-11-19 · 화면 크기: Windows 설정 따르기
- **결정**: 기본은 Windows 설정을 따른다. 디스플레이 배율(DPI)은 원래 모니터마다 따라가고, 접근성의 "텍스트 크기"(WPF가 스스로 안 따름)는 Foldy가 읽어 창 전체를 그만큼 키우며, 바꾸면 바로 따라간다. Ctrl+= / Ctrl+-는 그 위의 개인 조정, Ctrl+0은 다시 Windows 따르기. 더 보기 → 화면 크기(100~150%)도 있다.
- **왜**: "실버용"은 Windows에서 이미 정한 크기를 따르는 게 가장 단순하다.
- **다른 안**: Foldy만의 큰 글씨 설정 (Windows 설정과 따로 놀아 기각, 개인 조정으로만 남김).

## 2026-11-20 · AI·Claude 폴더 템플릿
- **결정**: 템플릿 3개 추가: Claude Code 프로젝트(CLAUDE.md, .claude/skills/이름/SKILL.md, .claude/agents, .mcp.json), Claude 스킬 하나(SKILL.md + reference.md + scripts/), AI 작업 폴더(prompts·data·outputs·evals). 공식 문서(code.claude.com/docs/en/skills) 기준: 스킬은 .claude/skills/<이름>/SKILL.md, frontmatter는 description 권장. .claude/commands는 예전 방식이라 넣지 않음. .claude·CLAUDE.md·AGENTS.md·SKILL.md가 있는 폴더는 AI 프로젝트로 보고 정리 도구가 구조를 건드리지 않는다. 단, 사용자 폴더(C:\Users\이름)의 .claude는 Claude Code 사용자 설정이라 프로젝트 표시로 보지 않는다.

## 2026-11-20 · 작업 태그
- **결정**: 태그의 원본은 각 폴더의 숨김 .foldy.md "파일 상태 태그" 칸(사람이 읽을 수 있는 목록). 디스크·PC를 바꿔도 폴더와 함께 간다. NTFS 대체 데이터 스트림은 USB·클라우드·zip에서 사라져 쓰지 않는다. Git·AI 폴더도 같은 방식이고, Git 안에서는 .git/info/exclude로 감추며(기본), [저장소에 공유]를 켜면 함께 올린다(켤 때 한 번 안내). 쓸 수 없는 폴더만 이 PC(tags-local.json)에 둔다. 기본 태그 4개(작업 완료·반영 완료·검토 중·제출 완료), Ctrl+D = 작업 완료. 칩은 이름 뒤 남는 자리에만.
- **왜**: 사용자 질문 "디스크가 바뀌면 DB 정보는 못 쓴다"에 대한 답. 파일 이름 우선 원칙.
- **미룸(0.9 뒤)**: 직접 태그 만들기, 태그로 찾기·거르기 캐시, Foldy 밖에서 옮긴 파일 따라가기, 파일 메모 한 줄.

## 2026-11-20 · 두 창 비교·맞추기
- **결정**: 크기+고친 시각(2초 오차)으로 비교, 내용 해시는 하지 않음. 한쪽에만 있는 파일은 지우지 않음(거울 맞추기 없음). 최신을 오래된 것으로 덮어쓰지 않음. 덮어쓰기는 이전 버전 보관(안 되는 드라이브는 옆 .foldy-bak), [되돌리기]. 지난번 맞춘 시각 뒤 양쪽 다 바뀐 파일은 하나씩 묻는다(10개까지). 창 안 색칠 대신 대화 창의 목록으로 보여 준다. Git·개발 프로젝트 폴더 안은 비교하지 않는다.
- **왜**: 단순·안정·되돌리기 원칙. 지우기와 해시는 위험·느림에 비해 얻는 게 적다.
- **다른 안**: 목록 색칠, 거울 맞추기, 내용 해시 (복잡도 때문에 0.9 뒤 검토).

## 2026-11-20 · 색인·분석 DB를 다른 PC나 드라이브로 옮겼을 때
- **결정**: 이미 되어 있는 방식을 그대로 쓴다. 색인 스냅샷은 볼륨 일련번호·USN 저널 ID·저장 위치·볼륨 경로가 하나라도 다르면 그 드라이브만 버리고 조용히 다시 만든다(Rust `persist::validate`, 테스트 `falls_back_when_snapshot_does_not_match_the_journal`). 폴더 분석 DB는 파일 이름이 볼륨 GUID라 다른 PC·다른 드라이브의 DB는 아예 맞춰지지 않는다. 저널이 없는 드라이브(USB·네트워크)는 색인하지 않는다.
- **왜**: 사용자가 물은 경우(DB 복사, 드라이브 교체)를 이미 막고 있다. 볼륨 GUID까지 스냅샷에 더 넣는 것은 디스크 복제처럼 내용이 같은 경우뿐이라 얻는 게 없다.
- **다른 안**: 스냅샷 형식을 바꿔 GUID 추가 (형식 변경 위험에 비해 이득이 없어 보류).

## 2026-11-19 · 메모 형식
- **결정**: 그림이 없는 메모는 그냥 .md. 그림을 넣는 순간 TextBundle 규격의 **.textpack**(zip: text.md + info.json + assets/)으로 바꿔 저장하고, 그림은 원본 화질 그대로 둔다. Foldy에서 .textpack은 메모 창의 [보기]로 열리고 [쓰기로] 고친다. 열 때 zip 안 이름(../, 절대 경로, :)을 거르고 개수·크기를 제한한다. 잠긴 메모는 확장명 .foldylock(이름.memo.foldylock) 그대로, 안의 본문은 Markdown(note.md + 그림). 예전 파일은 그대로 열린다.
- **다른 안**: 그림을 base64로 .md 안에 넣기 (파일이 커지고 다른 편집기에서 읽기 어려워 기각), 옆 폴더에 그림 두기 (파일이 흩어져 기각).
- **왜**: .md는 어디서나 열리는 표준이고, 잠긴 메모는 탐색기에서 자물쇠로 구별돼야 한다.

## 2026-11-19 · (기능 동결 예외) Markdown은 Foldy 뷰어로
- **결정**: .md를 열면 메모장 대신 Foldy의 읽기 전용 Markdown 뷰어(제목·목록·표·코드)가 기본. 뷰어에는 원문 보기와 편집기로 열기 버튼이 있고, 원격 이미지는 누르기 전에는 불러오지 않는다. 기존 설정도 한 번 바꿔 준다(설정 형식 2). .foldy.md도 같은 뷰어.
- **왜**: 사용자 요청. 이미 있던 뷰어를 기본으로 바꾸는 것뿐이라 새 기능이 아니다.
- **다른 안**: 등록된 앱 우선 유지 (메모장으로 열려 읽기 불편).

## 2026-11-19 · 금고 형식: Foldy 전용 강한 형식
- **결정**: 새 금고는 강한 키 유도(KDF)와 파일 이름 숨김을 쓰는 Foldy 전용 형식. 7-Zip 호환은 포기. 예전 금고(표준 AES zip)도 계속 열린다.
- **왜**: 리뷰에서 zip의 약한 키 유도와 금고 안 파일 이름 노출이 높음 위험으로 나왔다.
- **다른 안**: 표준 zip 유지 (다른 프로그램으로 열리지만 보안이 약함).

## 2026-11-19 · DRM 감지는 하지 않는다
- **결정**: 잠글 때 바이트를 그대로 넣고 풀 때 그대로 돌려준다. 미리보기는 확장자 모양이 맞을 때만, 아니면 "원래 프로그램으로 열어 주세요".
- **왜**: DRM 종류가 많아 머리 패턴을 다 알 수 없다. 그대로 돌려주면 DRM 파일도 그대로 동작한다.
- **다른 안**: 머리 패턴으로 감지 (틀리기 쉬워 기각). 제품 이름은 화면·문서에 쓰지 않는다.

## 2026-11-19 · 덮어쓰기 복구 범위
- **결정**: Foldy로 복사·이동하다 덮어쓰는 경우만. 원래 파일을 같은 드라이브의 숨김 보관 폴더로 옮겨 7일 보관(드라이브마다 2GB 또는 5% 중 작은 쪽). 시스템 드라이브는 %LOCALAPPDATA%\Foldy\이전 버전.
- **왜**: 같은 드라이브 이동은 즉시 끝나 느려지지 않는다. 다른 앱의 저장까지 가로채면 복잡하고 불안정하다.
- **다른 안**: 모든 앱의 저장 감시 (복잡해 기각), Windows 파일 기록에 맡김 (꺼져 있는 경우가 많음).

## 2026-11-19 · Git·AI 프로젝트 폴더는 구조를 건드리지 않는다
- **결정**: .git, .sln, package.json, .claude, CLAUDE.md, AGENTS.md 같은 표시가 있는 폴더 안은 정리·관리 방식 대상이 아니다. 담고 있는 위 폴더는 관리할 수 있고, 저장소는 통째로만 옮긴다.
- **왜**: 파일을 옮기면 빌드나 기록이 깨진다.

## 2026-11-19 · 사이드바 도구를 네 묶음으로
- **결정**: 🔍 찾기 · 🧹 정리하기 · 🔒 지키기 · 🔗 연결하기. 누르면 그 묶음의 메뉴. 정리 도구는 모두 같은 대화 창.
- **왜**: 버튼이 늘어 사이드바가 길어지고 한 화면 규칙이 깨졌다.
- **다른 안**: 버튼마다 사이드바에 하나씩 (스크롤이 생겨 기각).

## 2026-11-19 · GPL-3.0 오픈소스로 다시 공개
