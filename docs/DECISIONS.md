# 결정 기록

정한 것을 짧게 남긴다: 날짜, 무엇을, 왜, 다른 안. 최근 것이 위.

## 2026-11-21 · 업데이트는 늘 최신 버전으로 한 번에 (0.9.16, 사용자 요청)
- **경위**: "버전 차이가 많을 때 여러 번 업데이트하는 것 같다." 서비스는 확인할 때(6시간마다) 받은 버전을 준비해 두는데, 그사이 더 새 버전이 나와도 [재시작하고 업데이트]를 누르면 준비해 둔 예전 버전을 설치하고, 다음 확인에서 또 업데이트했다.
- **결정**: 설치 요청(InstallWhenIdle)을 받으면 설치 직전에 한 번 더 확인한다(지난 확인 결과에 기대지 않고). 더 새 버전이 있으면 그것을 받아 검증한 뒤 **그것으로 한 번에** 설치한다. 새것이 없거나 인터넷이 안 되면 준비해 둔 것으로 설치한다(설치를 막지 않는다). 기록: "설치 직전 확인: 더 새 버전 x로 바로 설치합니다". 시험: 상태 기계 테스트 2개.
- **MSI는 중간 버전이 필요 없다**: Foldy MSI는 메이저 업그레이드라 어느 버전에서든 최신으로 바로 올라간다.

## 2026-11-21 · 짧은 소개를 크게, 부드럽게 (0.9.16, 사용자 요청)
- **경위**: "동영상이 끊기고 내용이 작아서 안 보인다."
- **결정**: 끊김 원인은 0.033초마다 그림의 너비·위치를 바꿔 화면 배치를 매번 다시 한 것. 이제 그림 크기는 그대로 두고 변환(행렬)만 바꾸며, 모니터가 화면을 새로 그릴 때마다(CompositionTarget.Rendering) 움직인다. 진행 막대도 너비 대신 비율 변환. 장면이 바뀔 때 0.35초 동안 서서히 나타난다. 확대는 화면 캡처 원래 크기의 1.65~2배(글씨가 앱보다 크게 보이게), 누를 곳 둘레만 보인다.

## 2026-11-21 · 처음 소개는 쇼츠처럼 (0.9.13, 사용자 요청)
- **경위**: "주요 기능 소개를 처음 실행할 때 안내해 줘. 글을 읽기 싫어하니까 쇼츠처럼 동영상 화면으로."
- **결정**: 글로 된 5장짜리 둘러보기 대신, 세로 화면의 짧은 소개(ShortsWindow). 장면마다 실제 Foldy 화면(도움말과 같은 캡처)이 천천히 다가가고(줌·이동), 누를 곳에서 동그라미가 톡톡 뛰고, 글은 큰 한 줄 + 작은 한 줄. 5.5초마다 저절로 넘어가고 위쪽 막대가 몇 번째인지 보인다. 오른쪽을 누르면 다음, 왼쪽은 이전, Space 멈춤, Esc·[건너뛰기]는 언제든(같은 자리). 마지막 장은 [시작하기]. 장면(8개, 약 45초): 끌어다 놓기 복사, Ctrl+Space 찾기, 폴더 분석, 바탕화면 정리, 폴더 정리(0.9.14, 사용자 요청), 잠긴 메모, 폴더 구조 템플릿, Git. 처음 안에는 농구 장면이 있었으나 사용자가 "농구 소개는 빼고 좋은 기능을 더"라고 해서 빼고 분석·템플릿·Git을 넣었다.
- **왜 진짜 동영상 파일이 아닌가**: 동영상은 화면·문구가 바뀔 때마다 다시 만들어야 하고, 다국어·테마·글자 크기를 따를 수 없고, 설치 파일이 커진다. 실제 화면 캡처를 움직여 보여 주면 CI 화면 점검이 그 캡처를 늘 새로 찍으니 저절로 최신이고, 문구는 한 곳(Scenes)에 있어 나라별로 바꾸기 쉽다.
- **다시 보기**: 사이드바 아래 **?** 단추 → "짧은 소개 보기"(또는 더 보기 → 둘러보기). ? 단추는 짧은 소개와 사용 설명서(F1)를 고르는 메뉴가 됐다.
- **언제 저절로 보이나 (0.9.15, 사용자 요청)**: 처음 설치, **다시 설치**, **업데이트** 뒤 처음 켤 때 한 번. 기록(tour-shown.txt)에 "본 버전|시각"을 남겨, 버전이 다르면(업데이트) 다시, 같은 버전이어도 Foldy.exe가 기록보다 나중에 설치됐으면(다시 설치) 다시 보인다. 설정은 그대로라 글자 크기·밝기는 다시 묻지 않는다. 언제든 [건너뛰기].

## 2026-11-21 · 확인 창과 진행 창을 Foldy 모양으로 (0.9.12)
- **경위**: 사용자가 "업데이트 확인 창, 삭제 확인 창, 업데이트 진행 안내 창의 디자인이 본 프로그램과 다르다"고 했다. 13곳이 Windows 기본 메시지 상자(MessageBox)를 썼고, 진행 창은 WinForms 기본 모양(회색 바탕·초록 막대)이었다.
- **결정**: Foldy.UI에 Foldy 확인 창(FoldyDialog)을 두고 모두 바꿨다. 테마·강조색·화면 크기를 따르고, 글씨 16, 단추 높이 38, 단추에는 할 일을 쓴다(예: "비우기"/"그만두기", "지금 설치"/"나중에"). 되살릴 수 없는 일(휴지통 비우기, SFTP 삭제, 바뀐 서버 키, 문서 링크로 실행 파일 열기, 저장 못 한 메모 닫기 등)은 기본 단추가 [그만두기]다. 테스트(HangulRenderingTests.No_windows_message_boxes)가 MessageBox 사용을 막는다.
- **진행 창**: Foldy가 지금 테마의 색(바탕·글자·강조색·테두리)을 넘겨 PowerShell 창을 같은 색으로 그린다. 어두운 테마면 제목줄도 어둡게(DWM), 진행 막대는 강조색이 왔다 갔다 한다. 연주·우진 그림도 지금 테마 색으로 그려 어두운 바탕에서 이름표가 보인다.
- **한계**: 진행 창은 업데이트를 누른 그 순간 설치되어 있던 버전이 띄우므로, 새 모양은 0.9.12에서 다음 버전으로 올릴 때부터 보인다.

## 2026-11-20 · 업데이트 진행 창에 연주·우진 (0.9.10, 사용자 요청)
- **결정**: 업데이트 진행 창에 농구 장면을 넣는다. 설치하는 동안은 코트에서 드리블 기술(크로스오버·스핀·페이크)과 패스를 주고받는 1:1 같은 장면(반복), 끝나면 **연주가 패스하고 우진이 레이업 2점슛 → 하이파이브**(사용자: "1:1 농구", "우진이 레이업 2점슛", "연주도 패스하면서")를 한 번 보이고 창이 닫힌다. 새 장면 Layup을 더했다(덩크 장면을 바탕으로 가슴 패스·한 손 올려 넣기·림을 잡지 않음).
- **방법**: 진행 창은 Foldy가 닫힌 뒤 PowerShell로 뜨므로 WPF로 그릴 수 없다. Foldy가 닫히기 직전에 같은 그림 코드로 장면을 PNG(진행 80장·끝 40장, 0.1초 간격)로 그려 임시 폴더에 두고, 진행 창이 넘겨 보여 준다. 설정에서 애니메이션을 끄면 그리지 않고 글자만. CI 화면 점검(update-anim 장면)이 그림이 실제로 만들어지는지 확인한다.
- **배운 것**: PowerShell 변수는 대소문자를 가리지 않아 타이머를 `$anim`으로 만들면 매개변수 `[string]$Anim`에 들어가 문자열이 된다. 실제로 띄워 보고 잡았다.
- **다른 안**: 공을 뺏고 막는 진짜 1:1 동작 — 새 동작을 여러 개 그려야 해서, 지금은 있는 드리블 기술 장면을 쓰고 써 본 뒤 정한다.

## 2026-11-20 · 이미지만 보기는 켜져 있다고 말하기 (0.9.9)
- **경위**: 사용자가 "같은 폴더인데 왼쪽은 파일이 안 보인다"고 알렸다. 켜져 있는 Foldy를 화면 낭독기 정보로 보니 왼쪽 패널은 "이미지만 보기"가 켜져 있었고, 그 폴더에는 그림이 없어 빈 화면이었다. 무엇으로 켜졌는지는 기록이 없다(Ctrl+Shift+I를 함께 눌렀을 수 있다).
- **결정**: 이미지만 보기가 켜져 있으면 목록 바로 위에 "이미지만 보는 중이에요 · 그림 N개 (다른 항목 M개는 숨김)", 그림이 없으면 "이 폴더에는 그림이 없어요"를 보이고, 같은 자리에 [모든 파일 보기]를 둔다(켜고 끄기는 같은 자리, 수다쟁이 Foldy). UI 테스트가 켜기 → 안내·단추 → 끄기 → 목록 복귀를 지킨다.

## 2026-11-20 · 수다쟁이 Foldy와 업데이트 진행 창 (0.9.8)
- **경위**: 사용자가 [재시작하고 업데이트]를 눌렀는데 아무것도 보이지 않아 언제 되는지 몰랐다. 기록을 보니 업데이트는 됐다: Foldy가 닫히고 서비스(SYSTEM)가 뒤에서 설치한 뒤 다시 띄웠는데, 그 30초쯤 동안 화면에 아무것도 없었다. 그 전 두 번은 다른 Foldy 창(개발 중 자동 시험)이 떠 있어 서비스가 설치를 미뤘는데 그것도 알릴 길이 없었다.
- **결정 (원칙, 사용자)**: "과묵하면 답답하다, 수다쟁이 Foldy가 좋다." 디자인 원칙 1.4에 넣었다. 기다리는 일은 늘 무엇을 하는지·얼마나 걸리는지·끝나면 어떻게 되는지 말한다.
- **업데이트 진행 창**: 서비스는 화면을 띄울 수 없고 Foldy 실행 파일은 설치 중에 바뀌므로, Windows에 들어 있는 PowerShell로 임시 폴더에서 작은 창을 띄운다. 서비스의 업데이트 기록(updater.log)을 읽어 "Foldy가 닫히기를 기다리는 중 → 설치하는 중(1분 안) → 다시 여는 중"을 같은 자리에 보이고, 새 Foldy가 뜨면 닫힌다. 다른 Foldy 창 때문에 미루면 "다른 Foldy 창을 모두 닫아 주세요", 실패하면 "지금 쓰던 버전은 그대로예요, 다시 눌러 주세요", 5분 넘으면 직접 열어 보라고 말한다. 기록 문구가 바뀌면 창이 못 읽으므로 시험(UpdateProgressTextTests)이 지킨다.
- **보충 (사용자)**: "수다쟁이지만 확인 단추는 꼭 필요할 때만, 사용자는 게으르다." 알림은 상태 줄·스스로 닫히는 창으로, 단추는 되살릴 수 없거나 위험한 일에만. 업데이트 "최신 버전" 창과 폴더 분석의 휴지통 확인 창을 없앴다.
- **같이 점검한 곳**: docs/reviews/2026-11-20-chatty.md.

## 2026-11-20 · SFTP 단추와 서버 트리 펼치기 (0.9.7, 사용자 요청)
- **결정**: 탭 줄 오른쪽 드라이브 단추 끝에 드라이브와 같은 모양의 **SFTP** 단추를 둔다. "어디로 갈까"를 고르는 같은 자리라서. 누르면 연결 창(저장된 서버·새 연결)이 열리고, 단추가 있는 쪽 패널에 연다. 접속하면 서버 트리에서 처음 연 폴더와 /를 한 단계 펼친다(폴더마다 목록 한 번만, 더 깊이는 펼치지 않아 느린 서버도 부담이 적다).
- **다른 안**: 트리를 끝까지 모두 펼치기 — 서버 전체를 훑게 되어 느리고 화면이 길어져서 하지 않았다.

## 2026-11-20 · Git 표시를 쉬운 말로 (0.9.5, 사용자 동의)
- **경위**: 사용자가 "파일명 옆 M은 무엇이냐"고 물었다. M·A·?·!는 Git을 아는 사람만 읽는 약자라 "배워야 쓰면 실패" 원칙에 어긋난다.
- **결정**: 파일 목록의 Git 표시를 Git 화면과 같은 말로 바꾼다: **수정**·**추가**·**새 파일**·**충돌**(무시된 파일은 지금처럼 흐리게). 마우스를 올리면 Git을 몰라도 알 수 있는 한 줄 설명("마지막으로 저장한 기록(커밋) 뒤에 고친 파일이에요" 등). 표시가 이름을 덮으면 안 되므로(이름은 다 보여야 한다) 자리가 없으면 그리지 않고 설명은 툴팁으로.
- **다른 안**: 색 점만 찍기 — 색만으로는 뜻을 알 수 없고 색약 사용자에게 불리해서 하지 않았다.

## 2026-11-20 · 한글이 깨져 보이던 문제 (0.9.5)
- **경위**: 사용자가 설정 → 복사의 "스레드"가 "ㅅㄹㄷ"로, 설정 → 터미널의 "프로그램"이 깨져 보인다고 알렸다. 소스의 한글은 모두 완성형(NFC)으로 정상이었다. 원인은 글자 그리기 방식 **Display**: Pretendard 글꼴을 작은 크기로 픽셀에 맞춰 그리면 "스·레·드·그·프" 같은 글자의 획이 빠진다(0.3.21 둘러보기에서 "드"가 깨진 것과 같은 원인). 설정 창, 정보 창, 파일 목록, 이미지 보기, 레트로 테마가 Display를 쓰고 있었다.
- **결정**: 모든 화면을 **Ideal**로 그린다. 글자가 아주 조금 부드러워지지만 획이 빠지지 않는다. 테스트 `HangulRenderingTests`가 src 전체에서 Display 사용과 자모로 쪼개진 한글(NFD)을 막는다.
- **다른 안**: 화면마다 글꼴을 맑은 고딕으로 바꾸기 — 디자인이 갈라지고 같은 문제가 다른 글자에서 다시 날 수 있어 하지 않았다.

## 2026-11-20 · 색인 연결 회귀 (0.9.4)
- **경위**: 사용자가 빠른 검색에서 파일명에 들어 있는 낱말로 찾았는데 못 찾았다. 로그에 "색인 서비스에 연결하지 못함 (서비스 상태: Running)"이 계속 찍혔다. 보안 리뷰 L3로 넣은 "파이프 상대가 SYSTEM인가" 검사가, 보통 권한(중간 무결성)의 Foldy에서는 SYSTEM 프로세스를 열 수 없어(OpenProcess 거부) 진짜 서비스까지 거절했다. 그래서 빠른 검색과 Ctrl+F가 지금 폴더만 훑었다. CI는 관리자 권한으로 돌아 이 경우를 못 잡았다.
- **결정**: 서비스 관리자(SCM)에게 FoldyIndexer 서비스의 프로세스 번호를 물어 파이프 상대가 그 프로세스면 믿는다(보통 권한으로도 물을 수 있고, 서비스 등록은 관리자만 바꿀 수 있어 흉내 낼 수 없다). 그다음 기존 계정 검사(SYSTEM·나 자신). 서비스가 돌고 있는 PC에서는 실제로 연결되는지 테스트한다(서비스 없는 CI에서는 건너뜀). 색인에 연결되지 않으면 빠른 검색 아래에 ⚠로 "지금 폴더 안에서만 찾아요"를 분명히 보인다.
- **교훈**: 권한에 따라 갈리는 검사는 관리자·보통 권한 둘 다에서 확인한다. 개발 PC 수동 점검 M13으로 남긴다.

## 2026-11-20 · 빠른 검색 (Ctrl+Space, 사용자 요청·기능 동결 예외)
- **결정**: macOS Spotlight처럼 어디서든 Ctrl+Space로 화면 가운데 큰 검색 칸을 연다. 한 칸에서 찾는 것: Foldy 기능(명령), 파일·폴더(색인 DB, 색인이 없으면 지금 폴더 안), 앱(시작 메뉴 바로 가기), Windows 설정 항목(ms-settings:), 자주 쓰는/최근 폴더(위쪽에), 간단 계산·단위 변환(입력하면 바로 결과, Enter로 복사). 결과는 종류별 묶음, 맨 위에 "가장 알맞은 것" 하나, 오른쪽에 미리보기. Enter 열기·실행, Ctrl+Enter 들어 있는 폴더 보기, Esc·바깥 누르면 닫기. 기능은 띄어 쓴 낱말·초성(ㅅㅈ → 설정)으로도 찾는다.
- **말하듯 찾기·공통 기능 (사용자 요청, "복잡하면 하지 말고")**: 메모 쓰기·정리 도구·금고·설정 같은 Foldy 기능은 모두 명령 목록 한 곳에 등록돼 있어 빠른 검색에 저절로 나온다(새 기능도 등록만 하면 됨). "다운로드 정리해줘", "메모 쓸래"처럼 말하듯 쳐도 끝말을 다듬고(해줘·할래·쓸래 → 쓰기…) 기능마다 붙인 쉬운 말(QuickIntent.Keywords)로 맞춘다. 문장으로 물으면 "이걸 할까요? Enter를 누르면 시작해요"로 대답하고, Enter면 그 기능의 **기존 대화 창**이 이어서 한 단계씩 묻는다. 외부 AI나 전송은 쓰지 않는다.
- **하지 않은 것 (복잡해서)**: 검색 창 안에서 여러 단계 대화를 새로 만드는 것. 정리 도구들이 이미 대화 창으로 한 단계씩 묻기 때문에 그것을 그대로 쓰는 쪽이 단순하다. Ctrl+Space를 "Foldy에게 말 걸기" 하나의 입구로 삼아 첫 화면 버튼을 줄이는 것은 써 본 뒤 사용자 동의를 받고 정한다.
- **넣지 않은 것**: 웹 검색·사전(밖으로 아무것도 보내지 않는다). 태그·메모 내용·SFTP·Git 검색은 써 보고 정한다.
- **단축키 겹침**: 전역 단축키(RegisterHotKey)로 등록한다. 다른 프로그램이 이미 쓰거나, 중국어·일본어 입력기가 설치돼 있으면(Ctrl+Space가 입력 전환 키) 겹친다고 본다. 겹치면 조용히 넘어가지 않고 알리고, 비어 있는 키 후보(Ctrl+Shift+Space, Ctrl+Alt+Space, Ctrl+Alt+F, Win+Shift+F 중 실제로 비어 있는 것)와 [직접 눌러서 정하기], [Foldy 안에서만 쓰기]를 보여 준다. 확인은 처음 설정(글자 크기·밝기 다음)에서 하고, 업데이트 때는 묻지 않고 등록만 하다가 실패할 때만 알린다. 설정 → 단축키에서 언제든 바꾼다. 시험용 실행(FOLDY_DATA_DIR)에서는 등록하지 않는다.
- **찾기 장면: 냄새 잘 맡는 블러드하운드 (사용자 결정)**: 파일을 찾으면 축 늘어진 귀와 이마 주름의 블러드하운드가 코를 바닥에 대고 킁킁 → 귀를 펄럭이며 쌩 달려가 → 폴더를 물고 꼬리를 흔드는 0.5초 장면과 "킁킁! 0.03초 만에 1,284개 물어 왔어요"를 보인다. 못 찾으면 고개를 갸웃한다. Foldy 고유의 단순한 도형 그림(특정 캐릭터 아님), 대사는 한 곳(나중에 리소스)에. 애니메이션은 Windows 애니메이션 설정이 아니라 Foldy 설정의 "애니메이션 사용"을 따른다(농구 애니메이션과 같음).
- **처음 안("엄마 찬스")을 바꾼 이유**: "엄마는 뭐든 다 해 준다"는 고정관념을 담을 수 있고 엄마의 수고를 가볍게 다룬다는 의견이 있었다. 냄새로 찾는 개는 어느 문화에서나 "잘 찾는다"로 바로 읽히고 누구의 역할도 정하지 않는다.
- **다른 안**: Foldy 창 안에서만 여는 단축키 — 사용자가 "macOS처럼"을 원해 전역으로. 끄고 싶으면 [Foldy 안에서만 쓰기].

## 2026-11-20 · 빨리 지우기 (사용자 요청·기능 동결 예외)
- **결정**: 지우려는 곳에 파일이 **5,000개 이상**이면 지우기 전에 대화 창으로 묻는다. [휴지통으로 (되살릴 수 있어요)]가 기본, [빨리 지우기]를 고르면 "휴지통에도 남지 않아 되살릴 수 없어요, 중간에 멈춰도 이미 지운 것은 돌아오지 않아요"를 한 번 더 알리고, 그 확인의 기본 단추는 [그만두기]다(Enter 실수 방지). Shift+Delete(영구 삭제)로 지울 때도 같은 창이 나온다.
- **왜 5,000개**: Windows 휴지통은 파일 수천 개부터 눈에 띄게 느려지고(목록을 휴지통 데이터베이스에 하나씩 기록), 그보다 적으면 묻는 창이 오히려 방해가 된다. 세는 데는 2초까지만 쓰고, 다 못 세면 "○개 넘게"로 보인다.
- **방법**: 외부 명령(robocopy·rd) 없이 Foldy가 직접 병렬로 지운다. 폴더마다 안의 파일을 여러 스레드로 지우고(로컬 드라이브는 CPU 수×2, 최대 16), 비면 가장 깊은 폴더부터 지운다. 네트워크 드라이브는 동시에 4개만(회사 보안 드라이브 같은 느린 곳도 무리하지 않게). 읽기 전용·숨김·시스템 속성은 풀고 지운다. 긴 경로(260자 넘음)도 지운다. 정션·심볼릭 링크는 **링크만 지우고 안으로 들어가지 않는다**(다른 곳의 원본 보호). 작업 창에 지운 개수가 보이고 언제든 [취소]할 수 있다.
- **지우지 않는 곳**: 드라이브 맨 위, Windows, Program Files, ProgramData, 사용자 폴더 자체, 바탕화면·문서 폴더 자체는 빨리 지우기를 거절한다(휴지통으로만).
- **구현 위치**: 처음에는 Rust 엔진 안에서 하려 했으나, 하는 일이 "파일 하나씩 DeleteFileW"라 C#(.NET 파일 API = 같은 Win32 호출)으로 Foldy.Core에 두었다. 같은 병렬 방식이고 테스트(링크 보호·긴 경로·취소·보호 경로)를 쉽게 붙일 수 있다. 엔진 경계(FFI)를 늘리지 않는다.
- **애니메이션**: 영구 삭제와 같은 "경기장 밖" 장면.

## 2026-11-20 · 색인·분석 DB를 다른 PC나 드라이브로 옮겼을 때
- **결정**: 이미 되어 있는 방식을 그대로 쓴다. 색인 스냅샷은 볼륨 일련번호·USN 저널 ID·저장 위치·볼륨 경로가 하나라도 다르면 그 드라이브만 버리고 조용히 다시 만든다(Rust `persist::validate`, 테스트 `falls_back_when_snapshot_does_not_match_the_journal`). 폴더 분석 DB는 파일 이름이 볼륨 GUID라 다른 PC·다른 드라이브의 DB는 아예 맞춰지지 않는다. 저널이 없는 드라이브(USB·네트워크)는 색인하지 않는다.
- **왜**: 사용자가 물은 경우(DB 복사, 드라이브 교체)를 이미 막고 있다. 볼륨 GUID까지 스냅샷에 더 넣는 것은 디스크 복제처럼 내용이 같은 경우뿐이라 얻는 게 없다.
- **다른 안**: 스냅샷 형식을 바꿔 GUID 추가 (형식 변경 위험에 비해 이득이 없어 보류).

## 2026-11-19 · 메모 형식
- **결정**: 그림이 없는 메모는 그냥 .md. 그림을 넣는 순간 TextBundle 규격의 **.textpack**(zip: text.md + info.json + assets/)으로 바꿔 저장하고, 그림은 원본 화질 그대로 둔다. Foldy에서 .textpack은 메모 창의 [보기]로 열리고 [쓰기로] 고친다. 열 때 zip 안 이름(../, 절대 경로, :)을 거르고 개수·크기를 제한한다. 잠긴 메모는 확장명 .foldylock(이름.memo.foldylock) 그대로, 안의 본문은 Markdown(note.md + 그림). 예전 파일은 그대로 열린다.
- **다른 안**: 그림을 base64로 .md 안에 넣기 (파일이 커지고 다른 편집기에서 읽기 어려워 기각), 옆 폴더에 그림 두기 (파일이 흩어져 기각).
- **왜**: .md는 어디서나 열리는 표준이고, 잠긴 메모는 탐색기에서 자물쇠로 구별돼야 한다.

## 2026-11-19 · (기능 동결 예외) Markdown은 Foldy 뷰어로
- **결정**: .md를 열면 메모장 대신 Foldy의 읽기 전용 Markdown 뷰어(제목·목록·표·코드)가 기본. 뷰어에는 원문 보기와 편집기로 열기 버튼이 있고, 원격 이미지는 누르기 전에는 불러오지 않는다. 기존 설정도 한 번 바꿔 준다(설정 형식 2). .foldy.md도 같은 뷰어.
- **왜**: 사용자 요청. 이미 있던 뷰어를 기본으로 바꾸는 것뿐이라 새 기능이 아니다.
- **다른 안**: 등록된 앱 우선 유지 (메모장으로 열려 읽기 불편).

- **결정**: 새 금고는 강한 키 유도(KDF)와 파일 이름 숨김을 쓰는 Foldy 전용 형식. 7-Zip 호환은 포기. 예전 금고(표준 AES zip)도 계속 열린다.
- **왜**: 리뷰에서 zip의 약한 키 유도와 금고 안 파일 이름 노출이 높음 위험으로 나왔다.

## 2026-11-19 · DRM 감지는 하지 않는다
- **결정**: 잠글 때 바이트를 그대로 넣고 풀 때 그대로 돌려준다. 미리보기는 확장자 모양이 맞을 때만, 아니면 "원래 프로그램으로 열어 주세요".
- **왜**: DRM 종류가 많아 머리 패턴을 다 알 수 없다. 그대로 돌려주면 DRM 파일도 그대로 동작한다.
- **다른 안**: 머리 패턴으로 감지 (틀리기 쉬워 기각). 제품 이름은 화면·문서에 쓰지 않는다.

## 2026-11-19 · 덮어쓰기 복구 범위
- **결정**: Foldy로 복사·이동하다 덮어쓰는 경우만. 원래 파일을 같은 드라이브의 숨김 보관 폴더로 옮겨 7일 보관(드라이브마다 2GB 또는 5% 중 작은 쪽). 시스템 드라이브는 %LOCALAPPDATA%\Foldy\이전 버전.
- **왜**: 같은 드라이브 이동은 즉시 끝나 느려지지 않는다. 다른 앱의 저장까지 가로채면 복잡하고 불안정하다.
- **다른 안**: 모든 앱의 저장 감시 (복잡해 기각), Windows 파일 기록에 맡김 (꺼져 있는 경우가 많음).

## 2026-11-19 · Git·AI 프로젝트 폴더는 구조를 건드리지 않는다
- **결정**: .git, .sln, package.json, .claude, CLAUDE.md, AGENTS.md 같은 표시가 있는 폴더 안은 정리·관리 방식 대상이 아니다. 담고 있는 위 폴더는 관리할 수 있고, 저장소는 통째로만 옮긴다.
- **왜**: 파일을 옮기면 빌드나 기록이 깨진다.
