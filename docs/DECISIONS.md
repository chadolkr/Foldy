## 2026-11-22 · 짧은 소개(쇼츠) 그림은 화면 언어를 따른다 (사용자 제보)
- **경위**: "영문판 쇼츠에 한글 화면 동영상이 나온다". 문구는 번역됐지만 그림은 한국어판 화면 캡처 하나뿐이었다.
- **결정**: 짧은 소개는 `help\images\<언어>\<그림>`이 있으면 그것을, 없으면 지금처럼 한국어판 그림을 쓴다. [건너뛰기]·[시작하기] 단추도 번역(tour.skip, tour.start). 언어별 그림은 `build/doc-screenshots.ps1 -Lang en -Out assets\help\images\en`으로 찍는다(FOLDY_LANGUAGE로 언어 고정).
- **언제 찍나**: 앱 화면 번역이 끝난 뒤(TranslationComplete). 지금 찍으면 반은 영어·반은 한국어인 화면이 된다. 샘플 폴더의 파일 이름(보고서_2026_Q1.docx 등)도 그때 언어별로 바꾼다.
- **다른 안**: 다른 언어에서는 그림을 숨기고 글만 (기능이 안 보여 기각).
- **소개 사이트도 같은 그림 (사용자 제보 "Pages에 화면캡처가 영문이나 다른 언어에서 한글 화면이다")**: 사이트도 `assets/help/images/<앱 언어>/`가 있으면 그것을, 없으면 한국어판 `docs/images`. 한 번 찍으면 앱 쇼츠와 사이트가 함께 바뀐다. 한국어판으로 대신한 그림이 있을 때만 "화면 사진은 한국어판" 한 줄.
- **찍는 계획**: ① 앱 번역 완료(TranslationComplete = true) ② 샘플 폴더 파일 이름을 언어별로(DocShotsSandbox) ③ 노트북에서 `doc-screenshots.ps1 -Lang en|es|ja|zh-Hans -Out assets\help\images\<언어>` 네 번 ④ 눈으로 훑고 PR. 사이트와 쇼츠는 코드 수정 없이 바뀐다.

## 2026-11-21 · 코드 서명 대신 Microsoft Store 먼저 (사용자 결정 → 아래 위 항목으로 확정)
- **경위**: SignPath Foundation 무료 서명 보류(2026-11-19, "인지도 신호 부족", 나중에 재신청 가능). "서명이 없으면 사용자가 불안해하며 설치를 꺼릴 것 같다" → "Certum과 Store 둘 다" → "Store만 진행해도 될까?" → Store 먼저, Certum은 Store 판이 돌아간 뒤에 정한다.
- **조사 결과**: 개인 개발자 Store 등록은 무료(신분증+셀카). Store는 MSIX만 무료로 서명해 주고, MSI를 그대로 올리려면 우리가 CA 인증서로 서명해야 한다. MSIX에는 SYSTEM 색인 서비스를 넣기 어렵다(제한 기능, "대부분 승인되지 않음"). 자세히는 [store.md](store.md).
- **선택지**: A. MSIX Store 판(무료, 서비스·자체 업데이트 없이: 검색·폴더 분석은 폴백 경로) · B. Certum(€49/년) 서명 + MSI 그대로 Store 제출(기능 그대로, 업데이트 방식 그대로).
- **개인정보**: 저장소와 Store 공개 정보에는 개발자 이름(David CHA)과 GitHub 주소만. 회사 정보는 넣지 않는다.
- SignPath용 release.yml 단계와 `.signpath/`는 변수가 없어 건너뛰므로 그대로 둔다(재신청 대비).

## 2026-11-21 · 다국어 Foldy: 한국어·영어·스페인어·일본어·중국어 (사용자 결정, 진행 중)
- **경위**: "Page를 영문과 한글 두 가지를 만들어야겠다. 그럼 Foldy도 다국어 버전으로 만들어야겠구나." "언어는 영어, 스페인어, 일본어, 중국어, 한국어. 이 정도면 될까?" → 중국어는 간체(zh-Hans)를 먼저.
- **범위**: 화면·메시지·확인 창·정리 도우미 대화·짧은 소개·도움말·README(영어판) 전부 (디자인 원칙 2-1).
- **방식**: 사용자가 읽는 글은 리소스(.resx)로 모은다. 기본 언어는 Windows 표시 언어를 따르고(지원하지 않으면 영어), 설정에서 바꿀 수 있다. 언어는 리소스 파일 하나를 더하면 늘어나게 만든다. 로그·버그 신고는 영어. 날짜·숫자는 Windows 지역 설정.
- **뼈대 (0.9.33)**: 글은 `assets/i18n/<언어>.json`(키 → 글) 한 곳, 원본은 `build/i18n/strings.py`(언어마다 빠진 글이 있으면 멈춤). .resx 대신 JSON을 쓴 까닭: 번역하는 사람이 바로 읽고 고칠 수 있고, 언어 하나 = 파일 하나. 코드는 `Loc.T("키")`·`Loc.F("키", 값)`, XAML은 `{loc:T 키}`. 시험이 언어마다 키·{0} 자리가 같은지, 한국어가 남았는지 본다. 옮기는 동안(App.TranslationComplete = false)에는 "Windows 언어 따르기"도 한국어로 시작하고, 설정에서 고른 언어만 적용한다(반쯤 번역된 화면을 막는다). 시험·문서 캡처는 FOLDY_LANGUAGE로 언어를 고정한다.
- **순서**: (1) 리소스·언어 전환 뼈대와 영어 README (2) 자주 보는 화면부터 옮기기(사이드바·메뉴·확인 창·상태 줄) (3) 정리 도우미·짧은 소개·도움말 (4) 번역 검수. 남은 한국어 글자는 시험으로 찾아낸다.

## 2026-11-21 · 제품 소개 사이트: Astro + GitHub Pages (사용자 승인)
- **경위**: "foldy 앱 소개 제품 웹사이트를 만들고 싶다. 무료로 만들 수 있는 곳" → Astro + GitHub Pages 추천에 "응". 방향은 "심플 모던 쉽고 자세하게".

- **내용 순서**: 한 줄 소개(큰 줄 "빠르고 똑똑한 파일 관리자, 오프라인에서도", 작은 줄 "AI와 연결하면 더 편하게") → 숫자 셋(0.003초·무료·오프라인) → 사이드바와 같은 순서의 네 기능(무엇이든 찾기, 공간 늘리기, 바탕화면·다운로드·폴더 정리, 템플릿으로 폴더 만들기)을 기능마다 설명·쓰는 법·약속 한 줄과 실제 화면으로 → 매일 쓰는 기능 카드 → AI 연결(하나 더, 메인 아님) → 안심(오프라인·로컬 색인·추적 없음·오픈소스) → 왜 오픈소스인가요 → 설치 3단계(서명 없음 안내 포함) → 묻고 답하기.

- **말하듯 찾기·공통 기능 (사용자 요청, "복잡하면 하지 말고")**: 메모 쓰기·정리 도구·금고·설정 같은 Foldy 기능은 모두 명령 목록 한 곳에 등록돼 있어 빠른 검색에 저절로 나온다(새 기능도 등록만 하면 됨). "다운로드 정리해줘", "메모 쓸래"처럼 말하듯 쳐도 끝말을 다듬고(해줘·할래·쓸래 → 쓰기…) 기능마다 붙인 쉬운 말(QuickIntent.Keywords)로 맞춘다. 문장으로 물으면 "이걸 할까요? Enter를 누르면 시작해요"로 대답하고, Enter면 그 기능의 **기존 대화 창**이 이어서 한 단계씩 묻는다. 외부 AI나 전송은 쓰지 않는다.
- **하지 않은 것 (복잡해서)**: 검색 창 안에서 여러 단계 대화를 새로 만드는 것. 정리 도구들이 이미 대화 창으로 한 단계씩 묻기 때문에 그것을 그대로 쓰는 쪽이 단순하다. Ctrl+Space를 "Foldy에게 말 걸기" 하나의 입구로 삼아 첫 화면 버튼을 줄이는 것은 써 본 뒤 사용자 동의를 받고 정한다.
- **넣지 않은 것**: 웹 검색·사전(밖으로 아무것도 보내지 않는다). 태그·메모 내용·SFTP·Git 검색은 써 보고 정한다.
- **단축키 겹침**: 전역 단축키(RegisterHotKey)로 등록한다. 다른 프로그램이 이미 쓰거나, 중국어·일본어 입력기가 설치돼 있으면(Ctrl+Space가 입력 전환 키) 겹친다고 본다. 겹치면 조용히 넘어가지 않고 알리고, 비어 있는 키 후보(Ctrl+Shift+Space, Ctrl+Alt+Space, Ctrl+Alt+F, Win+Shift+F 중 실제로 비어 있는 것)와 [직접 눌러서 정하기], [Foldy 안에서만 쓰기]를 보여 준다. 확인은 처음 설정(글자 크기·밝기 다음)에서 하고, 업데이트 때는 묻지 않고 등록만 하다가 실패할 때만 알린다. 설정 → 단축키에서 언제든 바꾼다. 시험용 실행(FOLDY_DATA_DIR)에서는 등록하지 않는다.
- **찾기 장면: 냄새 잘 맡는 블러드하운드 (사용자 결정)**: 파일을 찾으면 축 늘어진 귀와 이마 주름의 블러드하운드가 코를 바닥에 대고 킁킁 → 귀를 펄럭이며 쌩 달려가 → 폴더를 물고 꼬리를 흔드는 0.5초 장면과 "킁킁! 0.03초 만에 1,284개 물어 왔어요"를 보인다. 못 찾으면 고개를 갸웃한다. Foldy 고유의 단순한 도형 그림(특정 캐릭터 아님), 대사는 한 곳(나중에 리소스)에. 애니메이션은 Windows 애니메이션 설정이 아니라 Foldy 설정의 "애니메이션 사용"을 따른다(농구 애니메이션과 같음).
- **처음 안("엄마 찬스")을 바꾼 이유**: "엄마는 뭐든 다 해 준다"는 고정관념을 담을 수 있고 엄마의 수고를 가볍게 다룬다는 의견이 있었다. 냄새로 찾는 개는 어느 문화에서나 "잘 찾는다"로 바로 읽히고 누구의 역할도 정하지 않는다.
- **다른 안**: Foldy 창 안에서만 여는 단축키 — 사용자가 "macOS처럼"을 원해 전역으로. 끄고 싶으면 [Foldy 안에서만 쓰기].

## 2026-11-20 · 빨리 지우기 (사용자 요청·기능 동결 예외)
- **결정**: 지우려는 곳에 파일이 **5,000개 이상**이면 지우기 전에 대화 창으로 묻는다. [휴지통으로 (되살릴 수 있어요)]가 기본, [빨리 지우기]를 고르면 "휴지통에도 남지 않아 되살릴 수 없어요, 중간에 멈춰도 이미 지운 것은 돌아오지 않아요"를 한 번 더 알리고, 그 확인의 기본 단추는 [그만두기]다(Enter 실수 방지). Shift+Delete(영구 삭제)로 지울 때도 같은 창이 나온다.
- **왜 5,000개**: Windows 휴지통은 파일 수천 개부터 눈에 띄게 느려지고(목록을 휴지통 데이터베이스에 하나씩 기록), 그보다 적으면 묻는 창이 오히려 방해가 된다. 세는 데는 2초까지만 쓰고, 다 못 세면 "○개 넘게"로 보인다.
- **방법**: 외부 명령(robocopy·rd) 없이 Foldy가 직접 병렬로 지운다. 폴더마다 안의 파일을 여러 스레드로 지우고(로컬 드라이브는 CPU 수×2, 최대 16), 비면 가장 깊은 폴더부터 지운다. 네트워크 드라이브는 동시에 4개만(회사 보안 드라이브 같은 느린 곳도 무리하지 않게). 읽기 전용·숨김·시스템 속성은 풀고 지운다. 긴 경로(260자 넘음)도 지운다. 정션·심볼릭 링크는 **링크만 지우고 안으로 들어가지 않는다**(다른 곳의 원본 보호). 작업 창에 지운 개수가 보이고 언제든 [취소]할 수 있다.
- **지우지 않는 곳**: 드라이브 맨 위, Windows, Program Files, ProgramData, 사용자 폴더 자체, 바탕화면·문서 폴더 자체는 빨리 지우기를 거절한다(휴지통으로만).
- **구현 위치**: 처음에는 Rust 엔진 안에서 하려 했으나, 하는 일이 "파일 하나씩 DeleteFileW"라 C#(.NET 파일 API = 같은 Win32 호출)으로 Foldy.Core에 두었다. 같은 병렬 방식이고 테스트(링크 보호·긴 경로·취소·보호 경로)를 쉽게 붙일 수 있다. 엔진 경계(FFI)를 늘리지 않는다.
- **애니메이션**: 영구 삭제와 같은 "경기장 밖" 장면.

## 2026-11-20 · 색인·분석 DB를 다른 PC나 드라이브로 옮겼을 때

## 2026-11-19 · 메모 형식
- **결정**: 그림이 없는 메모는 그냥 .md. 그림을 넣는 순간 TextBundle 규격의 **.textpack**(zip: text.md + info.json + assets/)으로 바꿔 저장하고, 그림은 원본 화질 그대로 둔다. Foldy에서 .textpack은 메모 창의 [보기]로 열리고 [쓰기로] 고친다. 열 때 zip 안 이름(../, 절대 경로, :)을 거르고 개수·크기를 제한한다. 잠긴 메모는 확장명 .foldylock(이름.memo.foldylock) 그대로, 안의 본문은 Markdown(note.md + 그림). 예전 파일은 그대로 열린다.
- **다른 안**: 그림을 base64로 .md 안에 넣기 (파일이 커지고 다른 편집기에서 읽기 어려워 기각), 옆 폴더에 그림 두기 (파일이 흩어져 기각).
- **왜**: .md는 어디서나 열리는 표준이고, 잠긴 메모는 탐색기에서 자물쇠로 구별돼야 한다.

## 2026-11-19 · (기능 동결 예외) Markdown은 Foldy 뷰어로
- **결정**: .md를 열면 메모장 대신 Foldy의 읽기 전용 Markdown 뷰어(제목·목록·표·코드)가 기본. 뷰어에는 원문 보기와 편집기로 열기 버튼이 있고, 원격 이미지는 누르기 전에는 불러오지 않는다. 기존 설정도 한 번 바꿔 준다(설정 형식 2). .foldy.md도 같은 뷰어.
- **왜**: 사용자 요청. 이미 있던 뷰어를 기본으로 바꾸는 것뿐이라 새 기능이 아니다.
- **다른 안**: 등록된 앱 우선 유지 (메모장으로 열려 읽기 불편).

## 2026-11-19 · 금고 형식: Foldy 전용 강한 형식
- **결정**: 새 금고는 강한 키 유도(KDF)와 파일 이름 숨김을 쓰는 Foldy 전용 형식. 7-Zip 호환은 포기. 예전 금고(표준 AES zip)도 계속 열린다.
- **왜**: 리뷰에서 zip의 약한 키 유도와 금고 안 파일 이름 노출이 높음 위험으로 나왔다.
- **다른 안**: 표준 zip 유지 (다른 프로그램으로 열리지만 보안이 약함).

## 2026-11-19 · DRM 감지는 하지 않는다
- **결정**: 잠글 때 바이트를 그대로 넣고 풀 때 그대로 돌려준다. 미리보기는 확장자 모양이 맞을 때만, 아니면 "원래 프로그램으로 열어 주세요".
- **왜**: DRM 종류가 많아 머리 패턴을 다 알 수 없다. 그대로 돌려주면 DRM 파일도 그대로 동작한다.
- **다른 안**: 머리 패턴으로 감지 (틀리기 쉬워 기각). 제품 이름은 화면·문서에 쓰지 않는다.

## 2026-11-19 · 덮어쓰기 복구 범위
- **결정**: Foldy로 복사·이동하다 덮어쓰는 경우만. 원래 파일을 같은 드라이브의 숨김 보관 폴더로 옮겨 7일 보관(드라이브마다 2GB 또는 5% 중 작은 쪽). 시스템 드라이브는 %LOCALAPPDATA%\Foldy\이전 버전.
- **왜**: 같은 드라이브 이동은 즉시 끝나 느려지지 않는다. 다른 앱의 저장까지 가로채면 복잡하고 불안정하다.
- **다른 안**: 모든 앱의 저장 감시 (복잡해 기각), Windows 파일 기록에 맡김 (꺼져 있는 경우가 많음).

## 2026-11-19 · Git·AI 프로젝트 폴더는 구조를 건드리지 않는다
- **결정**: .git, .sln, package.json, .claude, CLAUDE.md, AGENTS.md 같은 표시가 있는 폴더 안은 정리·관리 방식 대상이 아니다. 담고 있는 위 폴더는 관리할 수 있고, 저장소는 통째로만 옮긴다.
- **왜**: 파일을 옮기면 빌드나 기록이 깨진다.
