# Foldy 디자인 원칙

> 문서 버전 1.0 (2026-11-19) · 새 화면·기능·PR은 이 문서를 따른다. 바꿀 때는 맨 아래 변경 기록에 적는다.

Foldy는 기능이 많다. 그래서 **처음 보는 화면은 파일 탐색기처럼 단순하게**, 나머지는 필요할 때 꺼내 쓰게 한다.
새 화면이나 기능을 만들 때 아래 원칙을 먼저 확인한다. Windows 앱답게 만들고, 다른 OS나 다른 제품의 모양을 흉내 내지 않는다.

## 1. 바탕이 되는 원칙과 출처

## 0. Foldy가 지켜 온 약속

- **단순함 우선**: 복잡한 기능은 오히려 안 하는 게 낫다.
- **파일 이름은 항상 전부 보이게**: 무엇을 더해도 이름을 자르지 않는다.
- **안전한 기본값**: 지우지 않고, 먼저 보여 주고, 늘 되돌릴 수 있게. 서버(SFTP)에서 지울 때는 꼭 한 번 더 묻는다.
- **친근한 대화형**: 충분히 설명해서 사용자가 이해하고 고르게 한다.
- **필요할 때 그 자리에서 한 줄 제안**: 기능을 찾아다니게 하지 않는다.
- **느린 드라이브는 목록 먼저**: 무거운 일(크기 계산, 미리보기, Git)은 뒤에서 비동기로.
- **Git·AI 프로젝트 폴더 구조는 건드리지 않는다**: 정리 도구는 저장소를 통째로만 다룬다.
- **공개되는 곳에 회사 정보 금지**: [no-company-info.md](no-company-info.md).
- **Windows다운 생김새**: Windows 11의 익숙한 패턴을 따르고, 다른 OS를 흉내 내지 않는다.

## 2. Foldy 규칙 (꼭 지킨다)

1. **첫 화면 = 파일 탐색기.** 두 창, 복사·이동, 검색만 눈에 띈다. 나머지는 사이드바 네 묶음(🔍 찾기 · 🧹 정리하기 · 🔒 지키기 · 🔗 연결하기) 안에 있다.
2. **필요할 때만 나타난다.** 고급 기능은 상황에 맞을 때 한 줄 제안으로 보인다(다운로드 폴더에 파일이 많을 때 "다운로드 정리" 등). 한 번에 하나만, 닫으면 다시 귀찮게 하지 않는다.
3. **한 화면에 주요 동작 하나.** 나머지는 [자세히 보기] 안으로.
4. **정리 도구는 모두 같은 대화 창.** 찾은 것 → 왜 중요한지 → 누르면 어떻게 되는지 → [주요 동작] [자세히 보기] [나중에] → 한 일과 둔 곳 + [되돌리기].
5. **안전한 기본값.** 저절로 지우지 않는다. 먼저 보여 준다. 늘 되돌릴 수 있다. 지우는 것은 휴지통으로.
6. **파일 이름이 다 보여야 한다.** 표시·배지·칩이 이름을 잘라서는 안 된다.
7. **쉬운 말, 같은 말.** 존댓말 해요체, 짧게. 같은 동작은 어디서나 같은 이름(예: "휴지통으로", "되돌리기", "자세히 보기", "나중에").
8. **키보드로 다 된다.** Enter = 주요 동작, Esc = 아무것도 바꾸지 않고 닫기, 모든 명령은 Ctrl+Shift+P.
9. **설정은 마지막 수단.** 대부분은 좋은 기본값으로 해결하고, 사람마다 정말 갈리는 것만 설정에 둔다.
10. **새 기능 전에 묻는다.** 이 기능을 빼면 누가 불편한가? 이미 있는 기능과 합칠 수 없나? 맥락 제안으로 충분하지 않나?

## 3. PR 점검표

- [ ] 첫 화면에 새 버튼이 늘었나? 늘었다면 하나를 뺐나, 묶음 메뉴나 맥락 제안으로 충분하지 않나?
- [ ] 파일 이름이 잘리지 않나? (좁은 창, 1366×768, 긴 이름)
- [ ] 지우거나 옮기기 전에 보여 주고, 끝나면 [되돌리기]가 있나? 지우는 것은 휴지통으로 가나?
- [ ] 문구가 해요체이고, 같은 동작에 같은 말을 썼나?
- [ ] 키보드만으로 되나? (Enter·Esc·Tab, 명령 목록에 있음)
- [ ] 버튼에 화면 낭독기 이름이 있나? 다크·밝은 테마 모두 읽히나?
- [ ] 느린·네트워크 드라이브에서 화면이 멈추지 않나?
- [ ] Git·AI 프로젝트 폴더 안을 건드리지 않나?
- [ ] 화면 캡처·문서에 회사 정보가 없나?

## 4. 점검 방법

- `build/doc-screenshots.ps1`로 장면을 찍고, `review-small`(1366×768)과 `review-dark`(다크 테마)를 꼭 본다.

- 화면에 새 버튼을 넣으면 하나를 뺄 수 있는지 본다.
