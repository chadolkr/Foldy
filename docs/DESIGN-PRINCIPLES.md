# Foldy 디자인 원칙

> 문서 버전 1.12 (2026-11-25) · 새 화면·기능·PR은 이 문서를 따른다. 바꿀 때는 맨 아래 변경 기록에 적는다.

Foldy는 기능이 많다. 그래서 **처음 보는 화면은 파일 탐색기처럼 단순하게**, 나머지는 필요할 때 꺼내 쓰게 한다.
새 화면이나 기능을 만들 때 아래 원칙을 먼저 확인한다. Windows 앱답게 만들고, 다른 OS나 다른 제품의 모양을 흉내 내지 않는다.

## 맨 처음: 디자인은 사람의 불편함에서 시작한다

> "디자인은 사람의 불편함을 해결해 주는 것에서부터 시작해야 한다." (사용자 2026-11-25)

화면을 그리기 전에 **누가, 어디서, 무엇 때문에 불편한지**부터 한 문장으로 적는다. 그 불편함을 풀지 못하는 디자인은 예뻐도 고치지 않는다. 예:

- 나이가 들수록 한눈에 보이는 범위가 좁아져, 화면 맨 아래 안내를 못 본다 → 안내는 시선이 있는 곳(마우스 포인터 바로 아래, 키보드면 글자를 쓰는 자리나 대상 옆)에 (규칙 11)
- "색인", "확장자" 같은 말은 처음 들으면 막막하다 → 쉬운 말 사전 (2-2)
- 확인 창이 자주 뜨면 읽지 않고 누르게 된다 → 확인은 되살릴 수 없는 일에만 (수다쟁이 Foldy)
- 설명서를 읽어야 쓸 수 있으면 이미 어렵다 → 할아버지 할머니도 편하게 (아래)

이 네 가지는 소개 페이지(site/)의 "누구나 쉽게" 칸에도 같은 순서로 쓴다. 원칙을 바꾸면 그 글도 함께 고친다.

## 맨 먼저: 할아버지 할머니도 편하게

모든 화면은 이 기준으로 본다. **설명서를 읽지 않고, 처음 보는 순간 쓸 수 있어야 한다.** 배워야 쓸 수 있으면 실패다.

- **큰 누르는 곳**: 버튼·메뉴·끌기 손잡이는 마우스를 한 번에 맞출 수 있게. 버튼은 32×32가 기본, 아무리 촘촘해도 28×28 이상(Fluent 기준). 끌어서 크기를 바꾸는 경계선은 보이는 선이 가늘어도 잡는 곳은 9px 이상. (UI 자동 테스트 `HitTargetTests`가 검사한다)
- **켜고 끄기는 같은 자리, 같은 버튼**: 숨긴 것을 다시 보이게 하는 버튼을 다른 곳에서 찾게 하지 않는다. 켜져 있으면 눌린 모양으로, 메뉴 항목은 체크 표시로 지금 상태를 보여 준다. 사용자의 시선이 머문 곳에서 끝나게 한다.
- **다른 앱과 이어 주는 것도 단추 하나**: 사용자가 설정 파일·프로토콜을 몰라도 되게 한다(예: AI 연결의 [AI에 연결]이 깔린 앱을 찾아 설정을 넣는다). 바꾸기 전에 백업하고, 기본은 꺼 두고, 바깥 앱에는 읽기만 허락한다.
- **같은 종류의 동작은 같은 모양**: 창의 한 부분을 접고 펴는 버튼(사이드바, 폴더 트리, 미리보기)은 모두 같은 패널 아이콘, 같은 켜짐 표시(눌린 배경), 같은 툴팁 규칙("○○ 숨기기/보이기")을 쓴다. 모양이 다르면 다른 일을 한다고 읽힌다.
- **창은 모두 Foldy 모양**: 확인·알림 창은 Windows 기본 메시지 상자 대신 Foldy 확인 창(FoldyDialog)을 쓴다. 테마(밝게·어둡게·레트로)·강조색·화면 크기를 따르고, 단추에는 할 일을 쓴다("비우기"·"그만두기", "예/아니요" 대신). Foldy 밖에서 뜨는 업데이트 진행 창도 지금 테마 색을 받아 같은 모양으로 그린다. 테스트가 MessageBox 사용을 막는다.
- **Foldy 아이콘은 하나**: 제목줄·작업 표시줄·설치 파일·바로 가기·정보 창·사이드바 머리에 같은 v2 모던 플랫 아이콘(assets/icons) 하나만 쓴다.
- **Windows 표준 방식 먼저**: 경계선을 끌어 크기 바꾸기, ≡ 버튼으로 접기, 오른쪽 클릭 메뉴처럼 이미 아는 방식을 쓴다.
- **아이콘은 뜻이 바로 보이게**: Windows·Segoe Fluent 표준 아이콘을 쓰고, 헷갈릴 수 있는 아이콘은 글자를 함께 쓴다. 아이콘만 있는 버튼에는 마우스를 올리면 툴팁이 나온다.
- **또렷한 대비, 쉬운 말, 실수해도 되돌리기**: 글자 대비 4.5:1 이상, 해요체의 쉬운 말, 지우거나 옮긴 것은 되돌릴 수 있게.
- **수다쟁이 Foldy**: 과묵하면 답답하다. 기다려야 하는 일(업데이트, 연결, 불러오기, 분석, 복사 준비, 뒤에서 하는 일)은 늘 지금 무엇을 하는지, 얼마나 걸리는지, 끝나면 어떻게 되는지를 친근하게 말한다. 아무것도 안 보이는 순간을 만들지 않는다. 실패하면 이유와 다음에 할 일을 쉬운 말로. **단, 누를 단추는 꼭 필요할 때만**(사용자는 게으르다): 알림·진행 안내는 상태 줄이나 스스로 닫히는 창으로, 확인 단추는 되살릴 수 없거나 위험한 일(영구 삭제, 보안 경고, 저장 안 된 내용 버리기)에만.
- **처음 실행 때 보기 편하게**: 글자 크기와 밝기를 실제 모양을 보며 먼저 고르게 한다(업데이트 때는 묻지 않고 알리기만).
- **제한은 미리 알려 시간을 아낀다** (사용자 원칙 2026-11-22): 크기·공간·개수·형식·권한처럼 끝까지 할 수 없게 만드는 제한이 있으면, 사용자가 시간을 들이기 **전에**(암호 입력·긴 작업 시작 전에, 가능하면 고르는 순간) 확인하고 쉬운 말로 알린다. 오래 진행한 뒤에야 "넘었어요"라고 하지 않는다. 제한이 없으면 "제한은 없어요"라고 말해 걱정을 덜고, 필요한 것(예: 빈 공간)을 함께 알린다. 알 수 없으면 막지 말고 하던 대로 한다.
  - **공간을 쓰는 작업은 빈 공간부터** (사용자 2026-11-22 "한참 작업하다가 공간이 부족해요라고 하면 사용자가 화날 거다"): 복사·이동·금고·잠그기·꺼내기·맞추기·압축·내려받기처럼 디스크에 쓰는 일은 시작 전에 대상 드라이브의 빈 공간(FAT32면 한 파일 4GB 한도도)을 보고, 될 때만 시작한다. 모자라면 아무것도 바꾸지 않고 "얼마 필요, 얼마 남음"을 알린다. 공통 부품 `DiskSpace`(Foldy.Core/Space), 복사 엔진은 계획 직후 `space.rs`.
  - **모자라면 바로 공간 늘리기로** (사용자 아이디어 2026-11-22): 안내에 [공간 늘리기] 단추를 두어 그 드라이브의 폴더 분석을 열고, 정리한 뒤 [다시 시도]·[다시 확인]으로 하던 일로 돌아온다. 새 화면은 만들지 않는다.

## 0. Foldy가 지켜 온 약속

- **단순함 우선**: 복잡한 기능은 오히려 안 하는 게 낫다.
- **파일 이름은 항상 전부 보이게**: 무엇을 더해도 이름을 자르지 않는다.
- **안전한 기본값**: 지우지 않고, 먼저 보여 주고, 늘 되돌릴 수 있게. 서버(SFTP)에서 지울 때는 꼭 한 번 더 묻는다.
- **친근한 대화형**: 충분히 설명해서 사용자가 이해하고 고르게 한다.
- **필요할 때 그 자리에서 한 줄 제안**: 기능을 찾아다니게 하지 않는다.
- **느린 드라이브는 목록 먼저**: 무거운 일(크기 계산, 미리보기, Git)은 뒤에서 비동기로.
- **Git·AI 프로젝트 폴더 구조는 건드리지 않는다**: 정리 도구는 저장소를 통째로만 다룬다.
- **공개되는 곳에 회사 정보 금지**: [no-company-info.md](no-company-info.md).
- **Windows다운 생김새**: Windows 11의 익숙한 패턴을 따르고, 다른 OS를 흉내 내지 않는다.

## 2. Foldy 규칙 (꼭 지킨다)

1. **첫 화면 = 파일 탐색기.** 두 창, 복사·이동, 검색만 눈에 띈다. 나머지는 사이드바 네 묶음(🔍 찾기 · 🧹 정리하기 · 🔒 지키기 · 🔗 연결하기) 안에 있다.
2. **필요할 때만 나타난다.** 고급 기능은 상황에 맞을 때 한 줄 제안으로 보인다(다운로드 폴더에 파일이 많을 때 "다운로드 정리", 사진 폴더에서 "이미지만 보기" 등). 한 번에 하나만, 닫으면 다시 귀찮게 하지 않는다. 기능을 알려 주는 제안은 평생 한 번, 그냥 두면 사라진다.
3. **한 화면에 주요 동작 하나.** 나머지는 [자세히 보기] 안으로.
4. **정리 도구는 모두 같은 대화 창.** 찾은 것 → 왜 중요한지 → 누르면 어떻게 되는지 → [주요 동작] [자세히 보기] [나중에] → 한 일과 둔 곳 + [되돌리기].
5. **안전한 기본값.** 저절로 지우지 않는다. 먼저 보여 준다. 늘 되돌릴 수 있다. 지우는 것은 휴지통으로.
6. **파일 이름이 다 보여야 한다.** 표시·배지·칩이 이름을 잘라서는 안 된다.
7. **쉬운 말, 같은 말.** 존댓말 해요체, 짧게. 같은 동작은 어디서나 같은 이름(예: "휴지통으로", "되돌리기", "자세히 보기", "나중에").
8. **키보드로 다 된다.** Enter = 주요 동작, Esc = 아무것도 바꾸지 않고 닫기, 모든 명령은 Ctrl+Shift+P.
9. **설정은 마지막 수단.** 대부분은 좋은 기본값으로 해결하고, 사람마다 정말 갈리는 것만 설정에 둔다.
10. **새 기능 전에 묻는다.** 이 기능을 빼면 누가 불편한가? 이미 있는 기능과 합칠 수 없나? 맥락 제안으로 충분하지 않나?

## 2-1. 다국어 준비 (새로 고치는 화면부터)

**범위**: 화면 글자만이 아니라 상태 메시지, 오류·경고 창, 정리 도구의 대화 내용, 둘러보기, 도움말까지 사용자가 읽는 글 전부. 실제 번역과 기존 글자 옮기기는 0.9 뒤에 한다.

1. 사용자가 읽는 글은 코드에 바로 쓰지 말고 리소스 파일(.resx)에 모은다.
2. 영어가 30~50% 길어도 잘리지 않게 버튼·메뉴·말풍선 폭을 고정하지 않는다.
3. 날짜·숫자·용량은 Windows 지역 설정을 따른다. 글자는 Ideal 방식으로 그린다(Display는 한글 획을 빠뜨린다, 테스트로 막음).
4. 문장 조각을 이어 붙이지 않고 "파일 {0}개"처럼 문장 하나로 쓴다 (언어마다 어순이 다르다).
5. 로그와 버그 신고 내용은 영어로 통일한다 (누구나 읽고 검색할 수 있게).
6. **유머·애니메이션은 세계 어디서나 통하게.** 말장난보다 그림만 봐도 웃음이 나는 장면(농구하는 아이들, 냄새 잘 맡는 블러드하운드)을 쓴다. 대사는 리소스에 두어 나라마다 바꿀 수 있게 하고, 특정 캐릭터·작품을 흉내 내지 않고 Foldy 고유 그림만 쓴다. 손짓·색·숫자처럼 문화마다 뜻이 다른 것, 성별·가족 역할의 고정관념(예: "엄마는 다 해 준다")은 피한다.

## 2-2. 쉬운 말 사전 (사용자 2026-11-25)

컴퓨터를 잘 모르는 분이 "색인" 같은 말이 어렵다고 했다. 토스처럼, 처음 듣는 사람도 바로 아는 말로 쓴다. 화면 글(한국어)에 왼쪽 말이 다시 들어오지 않게 LocalizationTests가 막는다. 다른 언어도 같은 뜻으로 쉽게 쓴다.

| 쓰지 않는 말 | 쓰는 말 |
| --- | --- |
| 색인 | 찾기 준비, 파일 목록 |
| 색인 서비스 | 빠른 찾기 도우미 |
| 지금 색인하기 | 지금 목록 새로 만들기 |
| 패널 | 창, 반대쪽 창 |
| 사이드바 | 왼쪽 메뉴 |
| 폴더 트리 | 왼쪽 폴더 목록 |
| 경로 | 위치 |
| 확장자 | 파일 형식 |
| 영구 삭제 | 완전히 지우기 |
| 템플릿 | 폴더 틀 |
| 위저드 | 폴더 만들기 도우미 |
| 관리자 권한 | Windows가 허락을 물어요 |
| 다크 / 라이트, 테마 | 어둡게 / 밝게, 화면 밝기 |
| 강조색 | 포인트 색 |
| 애니메이션 | 움직이는 효과 |
| 버그 신고 | 문제 알리기 |
| ~습니다, ~입니다 | ~해요, ~이에요 |

**그대로 두는 말**: Windows 도구 이름(제어판·작업 관리자 등), Git·터미널·SFTP 같은 개발자 기능의 말, 금고·잠긴 메모, 디스크에 만든 폴더 이름, PARA 같은 고유 이름, AI에게 주는 글(MCP). 무엇이든 찾기는 옛말로 찾아도 나오게 한다.
